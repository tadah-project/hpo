# Changelog

All notable changes to **Tadah.HPO** (hyper-parameter optimisation) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

- **`ANNEAL_PT` adaptive-ladder guardrails (D26) — behavior change for `LADDER_ADAPT=1` configs.** New `PARAM LADDER_MIN_GAP` (default `0.1`, `0` = off, must be `[0,1)`) floors every interior log-gap at that fraction of the mean gap via clamp-and-redistribute waterfilling: pairs whose acceptance is *gap-insensitive* (e.g. basin-offset-limited — run24 drove adjacent-rung ratios to 1.006–1.010 this way, en route to the documented D21 degenerate-pair failure where equal rungs exchange unconditionally) can no longer be contracted to the 1-ULP representability guard. Floored pairs are flagged in the update journal line (`floor-clamped=n/(K-1)`) and in a new trailing `at_floor` column of `hpo_temperature_ladder.tsv`. Additionally the controller now **freezes itself once equalized**: when for 3 consecutive updates every pair is within 2 binomial sigma of the pooled window acceptance (equalized to within the window's resolving power) or held at the floor while still below the mean, adaptation stops with an INFO line — continuing past that point only chases window noise (a 20-attempt window resolves no better than ±9 points at 20% acceptance). `LADDER_ADAPT_UPDATES` remains the hard cap. Endpoints, determinism, MPI aggregation, and eval counts are unchanged; `LADDER_MIN_GAP 0` restores the previous unbounded contraction.
- **`ANNEAL_PT` CLASSIC diagonal-RAM trust region (D27) — behavior change for `STEP_ADAPT_EVERY>0` configs.** New `PARAM STEP_TRUST_FACTOR` (default `64`, `0` = off, must be `>1`) clamps each dimension's adapted sigma to within that factor of the slot's post-warm-up calibrated baseline. The RAM's centred shape term is a mean-zero random walk with **no restoring force** and only a 1-ULP floor (`V_FLOOR_FRAC` is Corana-only), so per-dim sigma could drift arbitrarily far from its calibrated scale — run24 held dims at sigma/width ≈ 2e-10 for 70k epochs. The baseline encodes legitimate per-dim sensitivity (deliberately tiny sigmas on hypersensitive wide-box dims stay tiny); the clamp only bounds *drift*, and the representability floor/support cap still apply last so a coordinate can always move. The key is a hard error anywhere the RAM cannot run (CORANA, explicit `STEP`, `STEP_AUTO 0`, `STEP_ADAPT_EVERY 0`). Journal: the sigma/width block's `(last N epochs)` label is corrected to `(instantaneous V; …)` — the printed values were always the live per-slot V at print time, not a window aggregate — and a new `sigma dims at trust bound per slot (lo|hi of D)` grid reports pinned dims; the per-slot step-health window counters are no longer accumulated where nothing reads them (CORANA / `STEP_ADAPT_EVERY=0`).
- **`ANNEAL_PT` step warm-up: bracket-convergence acceptance and sensitivity classification (D28).** A coordinate that exhausts its attempt budget with a two-sided bisection bracket tightened to `upper <= 4x lower` now finishes **`bracket-ok`** at the bracket's geometric mean (within 2x of both edges, each measured on the wrong side of the acceptance band) instead of `unconverged` — run24 finished 949/2784 (34%) of its (slot,dim) calibrations "unconverged/unexplained" under the old two-consecutive-in-band rule, whose 4-sample batches cannot reliably certify. The remaining unconverged dims are classified when the best tested batch names the cause: **`insensitive`** (best alpha ~ 1 at every tested scale — the objective does not respond to the coordinate) or **`hypersensitive`** (best alpha ~ 0 — acceptance collapses at every tested scale), with an actionable HINT (drop/fix the dim; narrow or log-scale the OPTIM range). The calibration summary line now reads `ok= bracket-ok= … unconverged=N (insensitive= hypersensitive= unexplained=)`, and "unexplained" means genuinely unexplained. Status bits are appended (existing TSV/MPI encodings unchanged); behaviour change is limited to previously-misbehaving dims, which enter production at the bracket midpoint instead of the best-tested batch scale.
- **`ANNEAL_PT` reporting: time-aware new-best table, final swap window, epoch-line T (D29).** The end-of-run `new-best count per slot` table is cumulative since process start, so a run's initial transient fossilizes in it (run24's hot-slot counts all dated from the first ~500 of 20,457 bests and read as steady-state oscillation); a companion `last new best per slot (eval #; 0 = never)` table now separates "still contributing" from "transient fossil". The final summary also repeats the **last completed `SWAP_WINDOW` per-pair acceptance table** (falling back to a labelled partial window) next to the cumulative one, which averages late drift away — run24's bottleneck pairs ran at 1–3% in the final windows while the cumulative row still read 11–22%. The per-epoch `T=[...]` on the epoch line is now snapshotted at epoch start, i.e. the temperatures the epoch's rungs actually ran at, not the post-ladder-adapt/post-RT-cooling values. Table renderers are extracted to testable `pt_detail::format_slot_count_table` / `format_pair_table` helpers.
- **Adaptive, power-shaped `ANNEAL_PT` temperature ladders.** `LADDER_POWER` shapes the initial normalized log ladder (`1` remains geometric); opt-in `LADDER_ADAPT` uses independent MPI-aggregated pair windows and diminishing stochastic approximation to equalize adjacent swap rates while preserving the cold/hot endpoints, cooling trajectory, slot-resident state, deterministic budgets, and objective-call count. Gain/cadence/freeze controls are validated strictly, each update is journaled and written to `hpo_temperature_ladder.tsv`, and fixed endpoints plus `REPLICAS` remain the controls on absolute acceptance.
### Added
- **`PARAM SWAP_WINDOW` for `ANNEAL_PT`** controls the number of epochs in each windowed per-pair swap-acceptance table (default `20`); `0` disables windowed tables and retains cumulative reporting only.
- **`PC_SCRIPT_TIMEOUT` keyword — self-describing name for the per-`pc_script` wall-clock limit (formerly the root `MAXTIME`).** `MAXTIME` is kept as a working legacy alias so every existing `.hpo` keeps parsing; both feed the same per-script LAMMPS `timer timeout` (SECONDS), and if both appear the later line wins (a WARNING is emitted). This disambiguates the chronic confusion with the *OPTIMIZER-block* `MAXTIME` (a genuine whole-run wall-clock stop, unchanged) and with `PC_WORKER_TIMEOUT` (the outer per-worker-task hard deadline). A new startup diagnostic line now reports the effective per-script limit, which keyword supplied it, and the effective hard per-worker-task deadline — none of which had any startup diagnostic before.
- **Near-bound floor-step audit in the journal (ANNEAL family, CORANA only).** After every rung (serial), epoch (ANNEAL_PT), or T-step (ANNEAL_PA), the driver marks dimensions that are within one floor-step of an OPTIM bound while Corana `V[i]` is already at `V_FLOOR_FRAC*width`. This is a heuristic observation: inward proposals remain possible and the mark does not prove that the optimum lies outside the box. Milestone summaries report the bound, gap, floor, marked chains, and persistence so sustained occupancy can be inspected as possible bound pressure. The audit is enabled for single-process runs only; multi-rank PT/PA skip it because no global mark union is implemented.
- **Annealing boundary policy is explicit:** `PARAM BOUNDARY_MODE 0` (default) performs mirror reflection without a fixed fold-count cap (tested across finite-double extremes on the audited x86-64 platform); `1` redraws each offending coordinate as in Corana et al. Discarded redraws do not consume host-evaluation budget.
- **Live cross-rank global-best checkpoint.** Every process-local improvement competes synchronously for canonical `best_pot.tadah` under a cross-process lock; candidates use deterministic `(loss, rank, slot, eval)` ordering and a winning complete potential is flushed and atomically renamed into place. A confirmed fresh run discards an unrelated prior incumbent, while an explicit checkpoint resume retains and validates its canonical winner. MPI rank-local potentials use `best_pot.tadah.r<rank>` on every rank, including rank 0. A SIGKILL before rename can leave a hidden unique temporary file, which readers and later publishers safely ignore.

### Changed
- The annealing-defaults benchmark report now distinguishes matched from unequal-seed cells and preserves the raw conclusions: NS20/NT2/P0.05 median 0.59 beat matched NS5/NT2 median 1.41, no NS20/NT5 42-D cell was run, and the six-seed PACCEPT medians were not monotone (P0.20 0.33 versus P0.10 0.42).
- Journal SUMMARY lines report BOTH `wall=<ms>/eval (<N> ev/s)` — true wall-clock throughput over the window since the previous milestone, i.e. what the run delivers under the current parallelisation — and `latency=<ms>/eval` (was `avg=`), the mean per-evaluation wall time on its worker thread. When K evaluations are fully concurrent (ANNEAL_PT/PA, DLIB:GFS), latency can approach K× the wall cost and must not be read as throughput. The end-of-run PERFORMANCE section gains a `Wall per eval` line and relabels the latency mean accordingly.
- **ANNEAL-family validation is fail-fast.** `STEP_FRAC` must be finite and in `(0,1]`; `V_FLOOR_FRAC` is `[0,1]` with zero explicitly disabling the floor; count knobs must be integral; bounds must have finite `low < high` and finite width; explicit `T_MIN` must not exceed resolved `T_HOT`/T0; and all numeric knobs must be finite. CONFIG/INIT seeds require the exact transformed dimension, finite values, and membership in every transformed OPTIM interval. `L` under Corana, Corana adjustment knobs under classic, and `RESET_TO_BEST` under PA are rejected instead of ignored. So are explicit controls whose values would be discarded: `STEP` with `STEP_FRAC`; `T_HOT` with `T0_PROBES`/`T0_PACCEPT`; `REANNEAL=0` with `REANNEAL_SCALE`; PT `T_COLD` with `LADDER_SPAN`; and static PT (`RT=1`) with `T_MIN`. An empty log-scale mask is valid all-linear input; if a width-derived step underflows on a subnormal interval, the diagnostic requests an explicit positive `STEP`.
- Corana step vectors are clamped to `[V_FLOOR_FRAC*width, width]` at initialisation and adjustment, and incomplete `NS` cycles are not adapted. Progress lines report floor/cap saturation counts. `RESET_TO_BEST` remains active for serial/PT and is attributed to step 7 of the original Corana algorithm (also used by Brommer).
- `THREADS` is the total per-rank shared-pool width for PC_LAMMPS fan-out and MLIP train/predict; it does not multiply `OMP_NUM_THREADS`, which now controls only residual OpenMP kernels.

### Fixed
- **MPI annealing message sizes are checked before narrowing:** vector broadcasts/exchanges reject counts above `INT_MAX`; gather/scatter wrappers reject negative counts and cumulative displacement overflow; and ANNEAL_PT/ANNEAL_PA reject a `D+2` calibration payload that the MPI C API cannot represent before dimension-sized driver allocation, host evaluation, or collectives. ANNEAL_PA likewise rejects an unrepresentable population-state payload in that prologue.
- **ANNEAL proposal-scale semantics and PT/PA initialization are aligned:** `STEP`/`STEP_FRAC` mean Gaussian sigma for CLASSIC and uniform half-width `V` for Corana. Help, banners, comments, and tests now state the existing PT/PA `INIT_MODE 0` distinction: non-seed jitter remains Gaussian in both variants, using the CLASSIC sigma or the numeric initial Corana `V` as its standard deviation.
- **ANNEAL-family graded-FAILSCORE repair:** Metropolis decisions and chain/walker personal-best tracking now rank every finite loss below `FAILSCORE`, including the graded `[0.999*FAILSCORE, FAILSCORE)` band. Previously the shared feasibility check rejected that entire band, flattening the graded failure landscape and defeating downhill repair in classic ANNEAL, Corana, PT, and PA. T0 calibration and PA feasibility weighting/resampling deliberately retain the stricter `< 0.999*FAILSCORE` feasibility rule.
- **Failure values cannot report annealing convergence:** `STOPVAL`, the Corana `FTOL` plateau, and T0 calibration now require a feasible loss (`f < 0.999*FAILSCORE` when a ceiling is configured). A non-finite, graded-band, or at-or-above-ceiling value cannot satisfy `STOPVAL`; it also clears, rather than fills, an `FTOL` plateau window.
- **Graded-FAILSCORE arithmetic is range-checked:** severity saturation avoids overflow for finite inputs near the double limit; grading startup requires a finite positive `FAILSCORE < 1e300` whose four bands are strictly representable; and `PC_FAILPROBE --s0` requires a finite positive scale.
- **PA temperature and resampling edge cases are numerically defined:** the ESS solve brackets `dbeta` by scale, a rounded temperature endpoint is advanced by one representable step and its actual `dbeta` is used for both weights and ESS, geometric cooling progresses through subnormal temperatures, and systematic resampling cannot select a trailing zero-weight parent.
- **PT replica exchange handles temperature endpoints analytically:** equal-temperature/equal-loss, zero-temperature, and normalized infinite-loss limits are resolved before arithmetic; ordinary finite positive-temperature exchanges use a log-domain comparison.
- HPOLog non-finite-loss summaries now report the observed count and rate without inferring a cause; zero-evaluation runs explicitly report that the rate is unavailable, and the generic NLOpt failure description no longer attributes code `-1` to NaN values.
- **ANNEAL-family audit fixes:** OOB rates now use `oob/proposed`; T0 probe state is exception-safe; budget exhaustion during probes reports `MAXEVAL`; an unusable seed loss can re-anchor best state consistently; and probe diagnostics exclude non-finite/failure-band samples. Non-finite losses and values at or above the `FAILSCORE` ceiling can no longer poison a healthy chain, and REDRAW aborts after a bounded 4096 misses instead of hanging on a broken kernel.
- **PT/PA hard global budgets and aggregation:** deterministic global-slot initialisation respects `MAXEVAL` (including zero), final rank-0 re-evaluation no longer overshoots the cap, STOPVAL propagates promptly, and PA allreduces proposal/accept/OOB totals. PA `culled` is now `population - unique parents`.
- Multi-rank HPO now fails early unless the strategy is plain `TADAH:ANNEAL_PT` or `TADAH:ANNEAL_PA`; this makes the rank-local in-memory best/HOT state versus canonical cross-rank file ownership contract explicit and prevents unsupported checkpointed/decorated strategies from mixing those domains.

## [1.4.0] — 2026-07-14

### Changed
- **BREAKING — bump-support gate at `tadah hpo` startup (was warn-only).** For a compact bump channel (D2_Blip/D2_Blip5, DM_REAM bump density) under a hard **Cut_Dummy** cutoff, startup now HARD-ERRORS when (a) the seed pot's own bumps or (b) any OPTIM box corner (`CGRID` high bound + `SGRID` low bound) let a support `c + w/eta` reach past RCUT — a truncated overhang is an energy/force STEP at the cutoff (measured 139 meV/atom on a real Ta run whose OPTIM boxes permitted it, with 11/32 blips pushed past RCUT). Every violation is listed with the exact bound that fixes it; when RCUT itself is OPTIM'd the gate binds against its LOW bound. RCUT stays authoritative (never auto-extended); to search longer range, raise RCUT2B/RCUTMB in the config — NN sizing already covers OPTIM'd RCUT bounds. Smooth cutoffs (Cut_Poly/Cut_Cos/...) are exempt: they damp the overhang to zero, and overhang there is a legitimate idiom (all bundled examples are unaffected).
- Startup also WARNS that an `OPTIM RCUT*` line on a gated bump channel is a wasted search dimension (the gate keeps every support inside its LOW bound, so the cutoff value cannot affect the model).
- **`tadah refit` compact mode enforces the same invariant on the radial bump ladders** (`CompactConfig::hard_rcut`, set by the engine for phi/rho; a spilling tail is also fitted against no data — the sample window ends at rcut). Centre boxes are capped at rcut, a soft spill penalty steers the derivative-free EXPLORE, and `clamp_bump_support` projects every scored candidate back into the feasible set (+ coefficient re-solve) so selection stays fair; `joint_refine`/FUSE bound bump centres and re-clamp afterwards; a violating INIT anchor (pinned or not) is rejected up front with the minimal `--eta`. Standalone fits with `hard_rcut = 0` (the default) are bit-for-bit unchanged.
- **BREAKING — `PARAM T_INIT` renamed to `T_HOT`** (ANNEAL family). The old key is a hard error naming the replacement. Part of a unified PARAM vocabulary shared by the upcoming `TADAH:ANNEAL_PT` / `TADAH:ANNEAL_PA` parallel drivers (`T_HOT`/`T_COLD`/`T_MIN`/`RT` temperature family).
- **ANNEAL auto-T0 calibration rewritten** (was: mean pairwise |ΔE| over uniform-box probes — on real FAILSCORE-cliff landscapes it collapsed to `T0=1.0` (all probes fail) or `T0~1e16` (mixed), producing a stone-cold or never-cooling schedule). Now: the seed point is evaluated first, `T0_PROBES` sigma-scaled local probes are drawn around it from a dedicated RNG stream, and `T0 = median(uphill feasible-probe ΔE)/ln(1/T0_PACCEPT)` over feasible probes (loss < 0.999*FAILSCORE; the graded band remains excluded); if feasible probes contain no uphill move, the scale falls back to the median absolute feasible delta. A non-finite or failure-band seed triggers one uniform-box batch and re-anchors on the best feasible point; a landscape with no feasible probe is a hard error with remediation hints. `FAILSCORE` is plumbed into `OptimizerSpec::failscore` for this.
- **ANNEAL FTOL plateau now implements the actual Corana §4 rule**: stop when the END-OF-RUNG CURRENT value stays within `eps = max(FTOL_ABS, FTOL_REL·|f|)` of the previous `NEPS` end-of-rung values AND of the running best. The previous rule watched the monotone best-so-far, so it force-stopped after exactly `NEPS` rungs once the best stalled — even while the chain was productively exploring at high T.
- **ANNEAL `T_MIN` default is now `auto = T0 * 1e-6`** (~132 rungs at the shipped RT 0.90; was fixed `1e-12`, ~170+ rungs — budget-limited runs always died on MAXEVAL instead of reaching any convergence criterion). Explicit `PARAM T_MIN` unchanged.
- **`RESET_TO_BEST` now defaults to 1 under `CORANA 1`** (step 7 of Corana et al. 1987, also used by Brommer; recommended on FAILSCORE-cliff landscapes). Explicit `PARAM RESET_TO_BEST 0` restores the old behaviour.
- **ANNEAL-family defaults changed after a fixed-MAXEVAL grid** on one 42-D Kr EAM workload plus a 2-D control (`playground_anneal_defaults/`): `NT` 2 → **5**, `RT` 0.85 → **0.90**, and `T0_PACCEPT` 0.80 → **0.05** (`NS` remains 5). The evidence is workload-specific. On matched seeds 201-203, NS5/NT5/P0.05 had median best loss 3.35e-3 versus 1.41 for NS5/NT2/P0.05 and 5.45 for NS5/NT2/P0.80. The only 42-D NS20 cell was NT2/P0.05: its 0.59 median beat the matched NS5/NT2 median 1.41; no NS20/NT5 cell was run. Among the six-seed NS5/NT5 cells, PACCEPT was not monotone (P0.20 median 0.33 versus P0.10 median 0.42), while P0.05 had median 8.2e-3. These measurements motivated a starting default, not a workload-independent ranking.
- ANNEAL RNG streams are now decorrelated per consumer (chain proposals vs T0 probes) via salted `seed_seq` streams: toggling `T_HOT`/probe settings no longer shifts the proposal sequence for a given SEED, and cross-config comparisons stay aligned.
- `MULTISTART` now decorrelates per-start seeds (`seed + start_index`; was: every start reused the same SEED, so stochastic inner optimisers produced near-duplicate chains). The per-start seed is journaled.
- ANNEAL-family progress lines show `current/total` (`rung=4/57`, `epoch=3/23`, `step=2/12`): the total is the planned maximum — whichever of the T_MIN schedule or the remaining MAXEVAL budget binds first (plateau/STOPVAL may still end the run earlier; REANNEAL cycles update the total). Unbounded runs (pure-PT ladder with no MAXEVAL) keep a plain counter.

### Added
- **`LIB TADAH ALGO ANNEAL_PT` — parallel tempering (replica exchange)** over the shared annealing core. K replicas (`PARAM REPLICAS`, default `max(THREADS,2)`) run the classic or Corana stepper concurrently at a fixed geometric temperature ladder (`T_COLD..T_HOT`, slot 0 coldest; `T_HOT` auto-calibrated, `T_COLD = T_HOT/LADDER_SPAN`); adjacent pairs attempt Metropolis state swaps every `SWAP_EVERY` epochs with deterministic even/odd (DEO) pairing. Swaps move states `(x, f)`, not temperatures — the Corana step vector V stays with its slot. `PARAM RT < 1` turns the static ladder into a PT→SA cooling hybrid (ends at `T_MIN`). Cumulative per-pair swap acceptance is journaled, with windowed tables every `SWAP_WINDOW` epochs (default 20; 0 disables windows); 20–40% is a literature-derived starting heuristic, while measured ladder flow is the outcome diagnostic. Execution: persistent `std::thread` worker pool (`THREADS`, ships in every build including `TADAH_ENABLE_OPENMP=OFF`) over the one thread-safe `HPO_Host`; with `REPLICAS` fixed, a deterministic objective, and no timing-dependent stop, the same SEED gives the same evaluated set for any THREADS (per-replica RNG streams, per-pair swap-coin streams, deterministic budget slicing).
- **`LIB TADAH ALGO ANNEAL_PA` — population annealing** over the shared core. `POPULATION` walkers (default `4×THREADS`, min 16) anneal from `T_HOT` to `T_MIN`; each temperature step reweights by `exp(-Δβ·f)`, resamples (systematic resampling — one RNG draw, lowest variance; non-finite/failure-band walkers (including finite graded failures) receive zero weight when at least one feasible walker exists; an all-failed population skips resampling and continues geometric cooling), then runs `SWEEPS` rungs per walker. Adaptive schedule via `PARAM ESS_TARGET` (default 0.5): largest Δβ keeping ESS at target × feasible population, capped by `RT` per step; `ESS_TARGET 0` = pure geometric. Walker state `(x, f, V)` copies on resample; with `POPULATION` fixed, a deterministic objective, and no timing-dependent stop, per-slot RNG streams keep the evaluated set THREADS-invariant. Per-step journal line: T, ESS, unique parents, culled, finite fraction, population best.
- **`TADAH_HPO_MPI` CMake option (default OFF)** — distributes ANNEAL_PT replicas / ANNEAL_PA walkers over MPI ranks (contiguous slot blocks; rank 0 runs the T0 calibration and broadcasts; PT boundary pairs exchange via `MPI_Sendrecv` with both sides drawing the same per-pair coin; PA resampling is decided on rank 0 from the gathered population). Deliberately narrow: no ScaLAPACK, no `MPI_Trainer`, no binary rename — MPI appears only in `hpo_mpi.h` and the two parallel drivers; training stays rank-local and every rank's LAMMPS instances run on `MPI_COMM_SELF` (requires an MPI LAMMPS library — configure-time check — and `MPI_THREAD_MULTIPLE`; on Cray MPICH set `MPICH_MAX_THREAD_SAFETY=multiple`). Mutually exclusive with the legacy `TADAH_BUILD_MPI`. Fixed-name outputs gain a `.r<rank>` suffix on ranks > 0; at run end rank 0 re-evaluates the global best once so its `best_*.tadah` files carry the global winner. MAXEVAL is enforced globally (allreduced accounting + deterministic slicing), and the global REPLICAS/POPULATION count must be at least the MPI rank count.
- Examples: `18_anneal_pt`, `19_anneal_pa`, `20_anneal_corana` (the serial adaptive variant had no example).
- **`PARAM REANNEAL 0|1` (default 1) + `PARAM REANNEAL_SCALE` (default 0.25)** — when a schedule cools out (`T < T_MIN`) with budget left, the chain snaps to the best-so-far and repeats from `REANNEAL_SCALE^n * T0` only while that start can execute at least two rungs before crossing `T_MIN`; budget, time, STOPVAL, or plateau may stop it earlier (run15 lever: the fixed schedule truncated progress mid-improvement). Re-anneal count reported in the summary and stop line.
- `anneal_core.h` — host-independent building blocks shared by the ANNEAL family (knob parsing/validation with per-algo whitelists, Corana §4 plateau tracker, robust T0 estimator, mirror reflection, salted RNG streams), unit-tested directly in `test_anneal_core.cpp`.
- ANNEAL warns when SEED is set only inside the INIT block (it seeds the init strategy, not the annealer's proposal stream).

### Fixed
- **WARM init: a missing or unparseable seed file is now unconditionally FATAL**, independent of `WARM_ON_MISMATCH` (which governs seed-CONTENT mismatches only: missing parameters, out-of-box clamping). Previously the default `warn` policy printed one stderr line, returned an empty init, and the annealer silently started from the OPTIM box CENTRE instead of the seed — invisible in the journal and masked whenever the OPTIM boxes are centred on the seed values.
- ANNEAL dead knobs are now hard errors instead of silent no-ops: `XTOL_REL`/`XTOL_ABS`, `VECTOR_ARR`, `GRAD_STRATEGY`, unknown `PARAM` keys (typo guard), and `THREADS`/`POPULATION` on the serial annealer (pointing at `TADAH:ANNEAL_PT` / `TADAH:ANNEAL_PA`).
- `PARAM L` is no longer validated (or read) under `CORANA 1` — it is a classic-variant knob.
- ANNEAL best-so-far bookkeeping: `best_x` now always pairs with `best_f` (previously a T0 probe could lower `best_f` while `best_x` stayed at the seed, handing `RESET_TO_BEST` an inconsistent state).
- Example fingerprint tools: repeated hyperparameter column names (e.g. `OPTIM FIXWEIGHT (2-4)` → three `FIXWEIGHT` columns) are now disambiguated as `NAME[k]` consistently in BOTH `generate_fingerprint.py` and `compare_fingerprint.py`. Previously the generator's dict collapsed duplicates (last column won) while the comparator matched the FIRST column — any flat-direction move in a duplicated column then masqueraded as a regression (bit example 17). Fingerprints for examples 16/17 regenerated.
- PC_LAMMPS: the host now builds ONE candidate-potential object per (thread, evaluation) and shares it across every `clear`/`pair_coeff EXTERN` cycle of every script that thread runs (`LammpsRunner::run_script` shared-potential overload; was a full `LammpsTadah` reconstruction per `pair_coeff` — 75x per evaluation on run15-class setups). Bitwise-identical objective; the hot->cold early-reject barrier is unchanged.
- `LammpsRunner::run_script` takes the potential Context by const reference (was by value — one deep copy per sim per evaluation).
- Startup journal now logs the OpenMP pool width (`omp_get_max_threads` and `OMP_NUM_THREADS`) — the PC_LAMMPS script fan-out is capped by it.

### Fixed
- A throwing candidate-potential construction now marks the sim failed before any LAMMPS command executes (previously the EXTERN line could proceed with a null potential).

## [1.3.0-beta.1] — 2026-05-20

HPO underwent the largest restructure of any module in this release: new init strategies, resume/restart, varloss, dlib-BFGS local optimiser, the `TADAH:ANNEAL` driver family (classic + Corana adaptive variant), the `CERES` gradient-based optimiser family, and a regression-tested example suite.

### Added
- **Init strategies** — multiple ways to seed the HPO sweep (`CONFIG`, `RANDOM`, `LHS`, `SOBOL`, `WARM`); fully documented in the rewritten `hpo.rst`.
- **Resume / restart** — checkpointed long runs can be resumed from the most recent journal entry; backed by the new CORE checkpoint + signal-handler infrastructure.
- **Variance-of-loss (`varloss`) acquisition** — `--varloss` / `--outvar` flags select an alternative scoring function over a user-provided set of LAMMPS `equal`-style script variables; HPO now validates these variables exist before launching workers.
- Standalone **dlib BFGS local optimiser** — added alongside the existing nlopt path.
- `HPOLog` run journal — structured per-evaluation log written incrementally.
- Per-dataset validation metrics and stats output files.
- Per-thread `Trainer` / `TrainerHost` cache — when structural parameters do not change between evaluations, the cached object is reused via `Trainer::reinit()` instead of being reconstructed (large speed-up for sweeps that vary only weights or scalar regression parameters).
- **Reference example suite** under `HPO/examples/` with `run_reference_suite.sh` driver and per-example fingerprint files (`reference_fingerprint.json`) for regression testing.
- `TADAH_ENABLE_ASAN` CMake option.
- **`LIB TADAH ALGO ANNEAL` — classic Kirkpatrick/Metropolis Simulated Annealing driver** (refs: Kirkpatrick 1983; Metropolis 1953). Geometric cooling, fixed-shape Gaussian step in transformed-parameter space, Metropolis acceptance, auto-T0 calibration from a small uniform-bounds random walk (overridable via `PARAM T_INIT`). Tunable knobs: `T_MIN`, `RT`, `L`, `STEP_FRAC`, `T0_PROBES`, `T0_PACCEPT`. Honours `MAXEVAL`/`MAXTIME`/`STOPVAL`. Dispatched from `run_inner()` alongside `TADAH:RANDOM` / `TADAH:GRID`; reflects out-of-bound proposal components back into the box (high-dim robustness fix).
- **`ALGO ANNEAL` Corana adaptive variant** — opt-in via `PARAM CORANA 1` (refs: Corana, Marchesi, Martini, Ridella, *ACM Trans. Math. Soft.* 13:262, 1987; Brommer, Univ. Stuttgart MSc, 2003). Per-dim step vector `V[i]` adapts every `NS`-step cycle from the per-dim accept ratio (grows when rate > 0.6, shrinks when < 0.4); cools after every `NT` step-adjust cycles. Replaces classic's whole-vector Gaussian + fixed σ with one-dim-at-a-time uniform perturbation + adaptive σ — fixes the cold-T freeze that fixed-σ runs hit on continuous multimodal problems. Tunable knobs: `NS` (default 5), `NT` (default 2), `C` (default 2.0). Per-rung journal line shows `V=[V_min, V_max]`; banner shows `ANNEAL[CORANA]` vs `ANNEAL[CLASSIC]`.
- **`PARAM V_FLOOR_FRAC`** (default `1e-3`) — explicit lower clamp on `V[i]` as a fraction of bound width. Guards Corana against `V[i]` runaway collapse on `FAILSCORE`-cliff landscapes where every uphill ΔL ~ FAILSCORE rejects for any T, driving accept rate to 0.
- **`PARAM RESET_TO_BEST 1`** — step 7 of the original Corana algorithm (also used by Brommer): snap the chain back to the best-so-far point at the end of every cooling step. Gives Corana basin memory; addresses the high-T wander failure mode.
- `ANNEAL` journal trace — `hpo_run.log` records a banner echoing the resolved knobs, an extended T0 calibration line, per-cooling-rung summary lines, and an explicit `ANNEAL stopped: <reason>` end line. Lets users diagnose mistuned `T_INIT`/`RT`/`STEP_FRAC` from the journal alone.
- **`LIB CERES` family** — `LBFGS` (limited-memory BFGS, Wolfe line search), `WOLFE` (full BFGS, Wolfe line search), `NLCG` (nonlinear conjugate gradient), `STEEPEST_DESCENT` (Armijo line search). All four use Ceres' `GradientProblemSolver`; gradient via `DynamicNumericDiffCostFunction` (central differences; step from `PARAM fd_step`). The Ceres NLLS family is deferred at dispatch with a tailored error.
- **`OptimizerCaps` registry** — single source of truth for `(LIB, ALGO)` capabilities (`is_global` / `is_population` / `is_gradient_based` / `accepts_inner` / `accepts_multi_seed` + ftol routing discriminant). Adding new optimisers is now two changes (run-function + caps entry).
- **`PC_LAMMPS --hotvar <name> <min> <max> [<initial>]`** — declares a `PC_LAMMPS` line as *hot*: a two-phase evaluator. Hot scripts run alone in **phase A** of each iteration (in parallel with other hot scripts), expose a value via `variable <name> equal …`, and have it validated against `[min, max]`. Validated values are cached per `(script, name)` and propagated as `${<name>}` strings to every cold (no-`--hotvar`) `PC_LAMMPS` script in **phase B**. Multiple `--hotvar` flags per line allowed; phase A is parallel so no cross-references. Out-of-range hot values fail-score the iteration and skip phase B.
- **`PC_<METRIC> --skip-above <cap>` / `--skip-rel <ratio>`** — per-metric bad-pot pre-filter on `PC_EMAE`, `PC_ERMSE`, `PC_ErRMSE`, `PC_ERSQ`, `PC_FRMSE`, `PC_SRMSE`. Triggers fire *before* the LAMMPS phase, fail-scoring the iter when the metric exceeds the cap or `metric > ratio × running_best` for the same metric.
- **Pre-flight audit hook + per-iter health monitor** — wires the MLIP bound-validation pipeline into the HPO surface. Driven by blueprint keys `AUDIT`, `AUDIT_SAMPLE`, `HEALTH_LOG` (in CORE).
- **`EFILTER` / `FFILTER` forwarded from `--validation`** — the validation-side LOAD-TRANSFORMS path now respects the same energy/force filtering as training. Symmetric LOAD-TRANSFORMS log; mean-share breakdown.

### Changed
- **Major restructure** — init strategies, resume, varloss reorganised into clearly separated layers.
- `structural_params_changed` flag retired — the trainer now decides via `Trainer::reinit()` semantics whether a rebuild is needed.
- Best-pot writer rewritten (now v2 layout); flushes outputs on short runs even before the run ends.
- Include-file parsing is now case-insensitive.
- `run_lammps` is now two-phase (hot first, cold second). When no `--hotvar` is declared the behaviour is identical to before: phase A is empty, all scripts run in parallel in phase B. The previous per-script post-hoc range check is replaced by the explicit `--hotvar` declaration; the hot-value cache is now keyed on `(script, varname)` instead of just `script`.
- `best_pot.tadah` warmstart cache lines: `# HOT_A0 <script> <a0>` → `# HOT <script> <name> <value>`. The legacy format still parses on read.
- GitLab CI rewritten from scratch — replaces the auto-generated Auto-DevOps configuration with a hand-written pipeline (build, test, lint, docs link to umbrella, release).

All five knobs now live in `config.hpo` as `PC_LAMMPS --hotvar` / `PC_<METRIC> --skip-above` flags. Migration: replace `${hot_a0}` script convention with an explicit `--hotvar hot_a0 <min> <max> [<initial>]` on the producing `PC_LAMMPS` line; replace `TADAH_HPO_BAD_POT_ERMSE_MEV=N` with `PC_ERMSE … --skip-above N`.
- `PRIOR` init strategy (parser path and the in-tree `INIT_STRATEGIES.md` tutorial). The `CONFIG` / `RANDOM` / `LHS` / `SOBOL` / `WARM` chain replaces it.
- `INIT { INCLUDE_CONFIG }` flag and the chain-reordering behaviour it triggered.
- Engineer-facing reference notes `HPO/LOAD_TRANSFORMS.md` and `HPO/INIT_STRATEGIES.md` — their content was folded into the user-facing `hpo.rst` in Session B's doc audit, leaving the in-tree notes redundant.

- `rcut` optimisation path corrected.
- Linking errors when HPO was built with optional features enabled (multiple commits).

- `LammpsRunner` API alignment (after a brief revert/redo cycle).

## [1.2.0] and earlier (condensed)

The `v1.0.0` → `v1.1.1` releases were the "internal playground" era. HPO began life as a small NLOpt wrapper; releases in this period focused on build-system iteration so that HPO could co-build with LAMMPS (CMake + traditional make), `FAIL_SCORE` defaulting, the move to `PC_<type>` performance counters, and a sequence of small fixes. No published changelog covers this era; treat anything before `1.3.0-beta.1` as undocumented in the modern sense.
