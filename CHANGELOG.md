# Changelog

All notable changes to **Tadah.HPO** (hyper-parameter optimisation) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **Transient filesystem errors are retried before a write fails.** On
  network filesystems a lock, write, fsync or rename can fail for a moment
  (EBUSY, EAGAIN, ESTALE, ETXTBSY, EIO, ENOLCK, ETIMEDOUT, EDEADLK; EACCES
  only when the directory is on a network filesystem -- on a local disk it
  is a permission error and fails at once) and succeed when repeated. The
  durable best potential retries its whole lock → read → compare → replace
  transaction with exponential backoff (10 ms doubling to 2 s, ±20 %
  jitter), releasing its locks between attempts, until 30 s have passed
  since the first failure (the failing calls' own time counts; a call that
  blocks by itself can add its duration at either end). A retry that finds
  its own earlier rename in place (the directory fsync failed, or an NFS
  rename reported ENOENT after landing) completes that commit. Other
  permanent errors (ENOSPC, EROFS, ENOENT, ...) are not retried. The
  per-evaluation logs (`loss.tadah`, `outvar.tadah`, `params.tadah`,
  `stats.tadah` and their `best_*` twins), whose write errors were never
  checked, are appended one batch per writer drain
  (`io::RetryingAppendFile`): a failed batch -- a partial write included --
  is truncated back and rewritten, with ONE 10 s budget per drain shared by
  every file and `DUMP`/`BDUMP` archive (each still makes its own attempt,
  plus one immediate re-attempt after a permanent errno). A batch that
  still fails is dropped whole and reported with the rows lost, and that
  file gets single attempts until a write succeeds (repeats summarised, an
  INFO line when writes resume); the run goes on. Archives are written
  whole or not at all. After a shutdown signal retrying goes on for at most
  2 s (`BackoffPolicy::stop_grace`, per durable publication and per drain),
  so one blip after a scheduler's time-limit warning does not lose the
  in-flight best or the last rows. Every retry is a WARNING; DIAGNOSTICS
  gains `Transient I/O retries : N (best-potential a, per-eval
  logs/archives b); rows lost c; archives lost d` only when one of them is
  non-zero, so clean runs write byte-identical journals and files. New API:
  `durable_best::SysError` (errno, operation, path, `may_have_landed()`),
  `durable_best::Options` with `default_backoff()` and 4-argument overloads
  (the 3-argument forms keep the default policy), `io::BackoffPolicy`,
  `io::retry`. Test-only knobs: `TADAH_HPO_TEST_IO_FAULT="site,ERRNO
  [,skip=K][,count=N|always][,partial=B][,land][,latency=MS][;...]"` and
  `TADAH_HPO_TEST_IO_BACKOFF_MS="initial,cap,budget[,jitter]"`
  (`io::testing::ScopedFaults` in-process); with no faults installed an I/O
  call costs one relaxed atomic load. Tests: `test_durable_best.cpp`,
  `test_append_log.cpp`, `[durable_e2e]` in `test_hpo_fixweight_e2e.cpp`.

### Changed
- Journal status after an optimiser exception reads `FAILED -- <what>`
  (was `STOPPED with error: <what>`).
- RESTART with an NLopt inner optimiser now restarts on stagnation (the
  `StagnationStop` ended as a graceful "nlopt failure"), and BASINS stages
  driven by NLopt see stagnation as stagnation, not convergence. MAXEVAL
  applies per launch, so a RESTART run can use up to (MAX + 1) x MAXEVAL
  evaluations.
- SIGINT/SIGTERM/SIGUSR2 during NLopt, a MULTISTART start, PT/PA
  calibration or NOISE_CALIBRATION ends as `SHUTDOWN (<signal>)` with exit
  code 0 on single-process runs. In a multi-rank `TADAH_HPO_MPI` PT/PA run
  the ranks other than 0 still end `FAILED -- ...: rank 0 aborted during
  ... calibration`, exit code 1.
- `NLOPT_ROUNDOFF_LIMITED` is a graceful stop (was FAILED); an error inside
  an NLopt gradient (e.g. a GRAD_STRATEGY ANALYTICAL wiring error) fails
  the run.
- A transient durable-best failure can hold the evaluations whose loss may
  become the new best for up to about 30 s (the others carry on).
- DIAGNOSTICS says `[ok] Every evaluation produced a usable loss.` only
  when that is so (not next to NaN/Inf clamps, not when no evaluation
  produced a loss), and its note calls the best potential complete only
  when one was persisted.
- `StagnationStop` moved to namespace scope (`tadah/hpo/stagnation_stop.h`;
  `HPO_Host<...>::StagnationStop` is an alias). New
  `host_analytical_grad_fn()` (`gradient_provider.h`).
- Numerics shift at the rounding level: a start point the plain map
  rounded is now evaluated exactly (3e-11 relative for a small weight in a
  wide box), and grids, LSCALE/ESHIFT and LAMMPS read-backs are unrounded,
  so first losses and possibly trajectories differ from 1.5.0 at that
  level; `OPTIM_SCALE NONE` runs are no longer byte-identical to earlier
  releases.
- Examples: `common/lammps/Ecoh.in` and `Ecoh_param.in` pass values to and
  from LAMMPS exactly (see Fixed), which exposes the ~1e-13 relative
  re-evaluation noise of the warm-started lattice relaxation. Examples 05,
  13 and 16 have new reference fingerprints; best losses, loss components
  and pinned hyperparameters are unchanged. In 05 that noise decides
  whether DLIB:BFGS's line search accepts a re-evaluation on the clamped
  bound RCUT2B = 6.0: 30 evaluations on the reference machine, 16 or 17
  after a 1-ulp perturbation (`evals_tol` 14 accepts 16..44). 13 sets
  `AFTER_STAGNATION 3` so both restarts still fire (23 -> 20
  evaluations); its restarts draw from `std::random_device`, so only what
  does not depend on them is pinned. In 16 the loss is flat along
  FIXWEIGHT(14), and which tied evaluation is best is no longer pinned.
  `examples/tools/generate_fingerprint.py` keeps hand-written fingerprint
  fields on regeneration.

### Fixed
- **Potential files are exact and never carry `NUMERIC`.** Every HPO
  potential writer (`best_pot.tadah` and its `.r<rank>` mirrors, `DUMP`
  `pot_<N>.tadah`, `BDUMP` `best_pot_<N>.tadah`) goes through
  `Context::write_potential`: every non-integer number with NUMERIC
  significant digits, default 18, so a best potential re-parses to exactly
  the doubles the evaluation used. The old writer default-inserted and
  wrote `NUMERIC 12` into every 1.5.0 potential; such a potential used as
  a configuration makes that line an explicit setting, so `tadah hpo`
  writes 12-digit potentials and prints a WARNING (`hpo_run.log` and
  stderr) naming the line. *Migration:* delete `NUMERIC 12` from
  configurations made from 1.5.0 potentials. The `# HPO_BEST_*` and `# HOT`
  header lines are unchanged. Tests: `test_hpo_pot_digits.cpp`,
  `[fixweight_e2e]`.
- **Values read back from LAMMPS are exact.** `LammpsRunner::get_variable`
  evaluates equal-style variables with `compute_equal` and renders the
  double losslessly; LAMMPS' `retrieve()` used `%.15g`, so every PC_LAMMPS
  outvar, hot value, failvar and gradient observable lost up to ~2
  significant digits. Other styles are returned verbatim. Inside a script
  LAMMPS still expands `${name}` and `v_name` of equal-style variables with
  15 digits; `hpo.rst` ("Precision of values passed to and read from
  LAMMPS") gives the lossless idioms, which the example scripts now use.
  Test: `test_lammps_variable_readback.cpp`.
- **Optimiser start points are evaluated at exactly their loaded values.**
  The real → internal → real map of the OPTIM dimensions is not the
  identity (in a `[-300, 300]` box a small weight came back 3e-11 relative
  off and `1.2e-14` as `0`), so even a `MAXEVAL 1` WARM run did not
  evaluate the input potential. Every optimiser run now anchors its start
  points (`anchor_seed_points`, `SearchSpace::with_seed_anchors`): CONFIG,
  WARM and INIT points, MULTISTART starts, RESTART refreshes, PRESTAGE
  top-K and BASINS pool seeds map back to their loaded doubles in every
  adapter, and a coordinate the optimiser has not moved keeps its seed
  value. NLopt BOBYQA/COBYLA/PRAXIS round the start before evaluating it,
  so any u within 4 ulp of the internal box of a seed maps to the seed
  (capped at 2^-27, below the finite-difference steps with the default
  `fd_step`, but never below 2 ulp of the seed). One exception remains:
  PRAXIS under `OPTIM_SCALE NONE` on a LIN box reaching 2^24 (1.7e7) can
  start a few ulp of the box off a seed of smaller magnitude than the box
  (`hpo.rst` gives the measured range). Tests: `test_search_space.cpp`,
  `test_seed_anchor.cpp`, `[seed_anchor]` in `test_hpo_fixweight_e2e.cpp`.
- **Knot-channel RCUT is re-derived exactly every evaluation.** A value
  within 1e-12 relative of the largest knot was kept, so the cutoff
  depended on what the thread evaluated before. Test:
  `test_rcut_autoderive.cpp`.
- Configuration and seed readers accept subnormal values (`1e-310`, which
  the lossless writers produce): the WARM reader skipped such a token and
  gave every later OPTIM'd dimension of the key its neighbour's value.
  Test: `test_init_strategies.cpp`.
- FAILSCORE clamps in outvar slots are exact (`failscore_token()`):
  `std::to_string` wrote 6 decimals, so `FAILSCORE 1.0000004` read back
  below the failscore and a failed `PC_FAILPROBE` passed as a real S(θ).
  Test: `test_failscore_token.cpp`.
- Validation ESHIFT is forwarded exactly (it had 6 significant digits), and
  `hpo_optim_resolved.hpo` writes its bounds exactly (10 digits), so the
  pasted block pins the box the run searched.
- **A fatal error fails the run, with a non-zero exit code.** NLopt's C++
  wrapper turns any exception from the objective into `NLOPT_FAILURE`,
  which the adapter treated as convergence: a best potential that could not
  be saved ended as `STOPPED -- nlopt failure (algorithm converged; ...)`,
  exit code 0, with a stale `best_pot.tadah`. The NLopt objective and
  gradient and Ceres' `Evaluate` now capture the host exception, stop the
  solver and rethrow it unchanged afterwards; NLopt's own exceptions are
  classified by type (`classify_nlopt_exception`). MULTISTART
  (`detail::run_start_guarded`) and the ANNEAL_PT/PA seed and T0
  calibration no longer swallow or retype run-level exceptions. `hpo_run()`
  also covers the fresh-run reset and NOISE_CALIBRATION, and closes the
  journal with `FAILED -- best-potential persistence: <error>` (other
  errors `FAILED -- <error>`) before rethrowing. Tests:
  `test_nlopt_host_exceptions.cpp`, `test_policy_host_exceptions.cpp`,
  `[durable_e2e]`; `tadah` exit status: `test_tadah_cli_exit_status.cpp`
  (Tadah.MLIP).
- **Parallel optimisers keep the most severe of concurrent exceptions.**
  The ANNEAL_PT/PA replica pool and ASA's block evaluations kept the first,
  so a stagnation stop or shutdown request caught first masked a concurrent
  persistence failure (the run could end COMPLETED, exit code 0). Errors
  now outrank a shutdown request, which outranks a stagnation stop
  (`exception_severity.h`). `DLIB:GFS` with THREADS > 1 no longer aborts
  (exit 134, journal left open) when two evaluations throw together.
- **RESULT reports a best potential that could not be saved.** It said
  `(none -- no evaluation produced a usable loss)` or named the older best.
  Now: `Best total loss : <loss> (eval N) -- NOT saved (best-potential
  persistence failed)`, `Last saved best : ...` when there is one, and
  `Best potential saved : not confirmed -- best_pot.tadah may hold eval N
  (write not synced) ...` only when the candidate's rename may have
  happened (not after e.g. EROFS). A lower best that another chain saved
  after the failure is the result, the lost candidate listed as `Unsaved
  candidate : ... superseded by eval M`. The record also backs the error
  up: the run fails on it even where a policy swallowed the exception, and
  a PRESTAGE, MULTISTART or BASINS stage that stops on stagnation ends the
  run at once.
- **After a fatal best-potential failure, later candidates get a single
  attempt.** Every new best of another chain queued behind the failure
  spent its own retry budget (a `DLIB:GFS` THREADS 8 run took 8 x 30 s to
  end). Once a publication has failed for good (`durable_best::FailLatch`,
  `Options::no_backoff`), later ones make one attempt without backoff: a
  transient or permanent error fails at once, and only a rename reporting
  ENOENT gets one immediate re-attempt. A failure is journalled as
  `best-potential persistence failure at eval K (no backoff after the
  failure at eval N): <error>`, the error ending in `(gave up after 1
  attempt over 0 s)` after a transient errno. Storage that has recovered
  still saves a later best (`best potential of eval K saved after the
  persistence failure at eval N (no backoff); the run still ends FAILED`),
  but the run ends FAILED with a non-zero exit and the first failure as its
  status (`detail::durable_failure_cause`). The GFS run above now ends
  after one budget when failing calls fail fast; with a soft-mount timeout
  of T s each of the up to THREADS - 1 queued candidates adds about T.
- **Evaluations that cannot become the new best no longer wait on best
  publication** (`HPO_Host::may_become_best`, a lock-free pre-check), so a
  publication's fsync or backoff holds up only the evaluations that may
  win; a stagnation check that would fire first waits for the new-best
  decisions in progress (`detail::throw_if_stagnated`). The rank-local
  mirror of an MPI run (`best_pot.tadah.r<rank>`) retries for at most 1 s,
  then makes single attempts until one succeeds.
- **MULTISTART, PRESTAGE and RESTART.** A MULTISTART whose every start
  fails now fails the run (it ended COMPLETED, exit code 0), and failed
  starts are noted in the status (`(N of M MULTISTART starts failed; see
  the WARNINGs)`, counted over the whole run). Under RESTART each
  MULTISTART start and each PRESTAGE refinement seed gets its own
  stagnation window (a start used to stop at its first evaluation after
  the first stagnation); MULTISTART relaunches all K starts after the last
  one, and PRESTAGE restarts only when the refinement stagnated without
  improving the best. An exhausted RESTART ends `STOPPED -- stagnation: no
  new best in W evals after R restart(s)` (was COMPLETED or a stale
  per-start status; example 13's fingerprint now expects it). `hpo_run()`
  starts with the stagnation window and top-K tracking disarmed: a policy
  that ended by an exception left them armed for a later run in the same
  process.

## [1.5.0] — 2026-09-10

### Breaking

Three changes require config or script edits. Each has an exact migration.

1. **`PARAM` values use the `ON` / `OFF` / `AUTO` vocabulary; numeric booleans
   and `0`-means-disabled are gone.** Every OPTIMIZER-block key that took `0`/`1`
   as a flag (`CORANA`, `RESET_TO_BEST`, `REANNEAL`, `LADDER_ADAPT`,
   `LADDER_FREEZE`) now takes `ON`/`OFF`, and every key where `0` used to mean
   "off" or "derive it yourself" (`SWAP_WINDOW`, `LADDER_MIN_GAP`,
   `STEP_TRUST_FACTOR`, `ESS_TARGET`, `INIT_JITTER_MAXEVAL`, `CHAIN_LENGTH`,
   `NT`, `REPLICAS`, …) takes `OFF` or `AUTO`. `BOUNDARY_MODE` became the enum
   `REFLECT` | `REDRAW`. The motivation was that `0` had come to mean three
   different things across neighbouring keys — `INIT_JITTER_MAXEVAL 0` meant
   AUTO while `INIT_JITTER_LADDER 0` would have meant OFF — which no amount of
   documentation makes readable in a config file. *Migration:* the old spelling
   is a hard error naming the new token, so nothing fails silently; run your
   config once and follow the messages. `PARAM CORANA 1` → `PARAM CORANA ON`,
   `PARAM SWAP_WINDOW 0` → `PARAM SWAP_WINDOW OFF`, `PARAM BOUNDARY_MODE 1` →
   `PARAM BOUNDARY_MODE REDRAW`.
2. **Every index a person reads is 1-based, in files as well as the journal.**
   Ladder slots, exchange pairs, walker lineages and pc-worker slots print from
   1 in `hpo_run.log`, in the TSV sidecars, and in `best_pot.tadah`'s
   `# HPO_SOURCE_SLOT` header. Internally these indices stay 0-based — they
   round-trip as identities through the warm-start cache and the resume
   checkpoint — so the conversion happens at the I/O boundary and the readers
   shift back by one. *Migration:* a script that parses a slot number from a
   Tadah file must subtract 1; a checkpoint written by 1.4.x still resumes
   (its header is read with the old radix).
3. **`ANNEAL_PT` scales the initial jitter along the ladder by default**
   (`PARAM INIT_JITTER_LADDER AUTO`, see below). This changes the starting
   population of every existing PT run at a fixed `SEED`. *Migration:*
   `PARAM INIT_JITTER_LADDER OFF` reproduces the 1.4.x placement exactly
   (verified byte-for-byte across the 600-cell performance matrix).

### Added
- **`PARAM INIT_MODE JITTER` no longer borrows `STEP_FRAC` for the initial displacement (`ANNEAL_PT`, `ANNEAL_PA`).** `JITTER` used the production step scale as its jitter sigma, so a run that wanted large proposals on a narrow temperature ladder had no way to say so without also scattering its replicas across the whole OPTIM box: at 816 dimensions and `STEP_FRAC 0.15` a "jittered" replica was 37 % of a full randomisation from the seed, which is not a warm start. `INIT_MODE` now takes a magnitude of its own in one of three forms. `JITTER` (unchanged default) keeps the `STEP_FRAC` coupling and the Gaussian draw. **`JITTER <fraction>`** sets sigma as that fraction of each OPTIM width. **`JITTER AUTO <p>`** MEASURES it: for every dimension the calibration finds the largest displacement whose loss stays inside `|L(sigma_d) - L0| <= p*|L0|`, by a two-sign screen at the per-side cap followed by a log-bisection, using the run's own `--hpotarget` objective. `FIXED` and `AUTO` draw uniformly on `+/-sigma` rather than from a Gaussian, because their sigma is a declared or measured BOUND and a Gaussian puts ~32 % of coordinates outside it. The calibration does **not** consume `MAXEVAL` (a `probe::Scope` marks the phase and the host exempts it, so no stagnation counter, restart policy or `durable_best` publication sees these evaluations either); it is bounded instead by `INIT_JITTER_MAXEVAL` (`AUTO` = the protocol's own worst case) and `INIT_JITTER_MAXTIME_FRAC` (0.25 of `MAXTIME`). Progress, a per-dimension sigma table (`hpo_init_jitter.tsv`), a per-status census and the resulting per-rung initial loss are journaled. Two cost levers for large search spaces: `INIT_JITTER_SAMPLE <n>` measures only `n` dimensions, chosen round-robin across parameter families, and lets the rest inherit their family's median sigma/width (measured on an 816-dimension space: 2 888 probes full, 256 at `SAMPLE 64`, an 11x lever), and `INIT_JITTER_AUDIT <n>` (default 32) re-probes sampled dimensions at `sigma/2`, since sigma is a grid certificate rather than a proof that the loss is monotone in displacement. Under MPI the dimensions are split into contiguous per-rank blocks and the sigma vector is broadcast, so every rank seeds from the same measurement.
- **`PARAM INIT_JITTER_LADDER` — per-slot scaling of the initial jitter (`ANNEAL_PT`), `AUTO` by default.** Slot `k` is displaced by `sigma_k = sigma_d * (T_k/T_HOT)^gamma`. Without it every non-seed slot was placed with the SAME displacement, so the coldest replica — whose job is to refine the seed — started as far from it as the hottest explorer, and a warm start survived only at slot 1. `AUTO` resolves to `gamma = 0.5`, which is equipartition (the equilibrium coordinate spread in a locally quadratic basin goes as `sqrt(T)`) and deliberately NOT a function of `LADDER_SPAN`: the span already enters through `T_k/T_HOT`, so making gamma depend on it too would count the same quantity twice. Scaled sigmas are floored at `resolvable_coordinate_scale` so a wide ladder cannot collapse the cold slots onto the seed, and the clamped count is journaled with a warning. `OFF` restores the 1.4.x placement; a number sets gamma directly. **Measured:** on a warm start (`ellipsoid6`, `LADDER_SPAN 1e6`, seed at 2 % of the default start) the default is 4x better on median best and wins 38 of 40 paired seeds. It is not a universal win — `rosenbrock6` from a MEDIOCRE seed at the same span is 1.22x worse on 40 of 40 seeds, because a curved valley reached from a poor starting point is exactly where you want the cold slots to spread out and hunt. That is what `OFF` is for.
- **Per-dimension Corana acceptance census (`ANNEAL_PT`) + `hpo_corana_acceptance.tsv`.** Corana's step adaptation was always per dimension (`adjust_corana_step` reads that coordinate's own accept/propose counts), but the journal only ever printed one rung-wide acceptance per epoch, so a run could sit at a healthy 30 % while hundreds of coordinates never moved and nothing said so. The counters that drive the adaptation could not be read after the fact either — they are an evidence window that is consumed and zeroed every `NS` sweeps — so `ChainState` now carries a never-reset parallel copy. The journal reports a median-acceptance and frozen-dimension grid at the `SWAP_WINDOW` cadence, and at end of run a per-slot percentile table (nearest-rank over the visited dimensions), the named extremes at the two ends of the ladder, and a HINT listing coordinates Corana accepted no move on at ANY temperature. The full per-`(slot, dimension)` table, with each slot's adapted `sigma` next to the acceptance it produced, goes to `hpo_corana_acceptance.tsv` (gathered across MPI ranks). Rows are per SLOT, not per walker: an exchange moves `x`/`f` between slots and leaves `V` and these counters behind — stated wherever a row is printed.
- **Multi-token `PARAM` values.** `PARAM` accepts a value list (`PARAM INIT_MODE JITTER AUTO 0.05`) under a per-key grammar rather than a maximum arity, because the two callers frame their input differently — `HPOTargets::read` is line-framed while `tadah refit`'s inline `OPTIMIZER` block is a flat token stream, where a greedy read would silently swallow the following block. An unexpected extra token is a hard error naming the key and the token.
- **Search-space scaling, phase 0 (registry-driven `STEP` policy, fail-fast startup checks).** `OptimizerCaps` gains a `StepUse` field that records how each backend consumes the OPTIMIZER-block `STEP` (NLopt, verified against nlopt 2.10 `optimize.c`: SBPLX/NELDERMEAD raw per-dim simplex edges; BOBYQA/COBYLA per-dim coordinate rescaling; NEWUOA/NEWUOA_BOUND/PRAXIS collapsed to the minimum; MMA/CCSAQ trust half-width; MLSL/AUGLAG forwarded to `INNER`; CRS/ISRES/ESCH/DIRECT*/STOGO/LD_LBFGS/VAR*/TNEWTON*/SLSQP ignore it) plus a one-line note printed by `tadah hpo` help and used in error text. A new `scale_validation` pass runs at the end of `HPOTargets` parsing (STEP policy) and inside `validate_hpo_setup()` (seeds + width audit): `STEP` on a backend that would drop it is a hard error with the backend's hint (previously DLIB:GFS and TADAH:RANDOM ignored it silently and every NLopt algorithm that never reads an initial step accepted it as a no-op); `STEP` must be finite and `> 0`; a `STEP` at STRATEGY level under `TYPE BASINS/BASINSV2` is rejected (it was silently dropped by the stage-spec builder); an outer `STEP` next to an `INNER STEP` under MLSL/AUGLAG warns that the outer value wins (NLopt behaviour); every resolved starting point must be finite, `> 0` on log-scaled dims and inside its OPTIM box (uniform across backends -- ANNEAL/ASA used to reject at run time, NLopt failed at optimize time with `bounds fail`, DLIB/CERES asserted or clamped); a startup INFO line reports the OPTIM width min/max/ratio and a WARNING names dims narrower than 1e-12 of their magnitude; `LN_NEWUOA` (called by NLopt without bounds) and every CERES algorithm (unconstrained `GradientProblemSolver`) get a startup WARNING that evaluations may leave the box. `STEP <KEY>[(indices)] <value>` per-key/per-index overrides are parsed (`OptimizerSpec::step_overrides`; consumed by the per-dimension step plan of the next phase). `LOG_HP` is now accepted at the `OPTIMIZER` (short-form) level as the docs always claimed (it threw `unknown key` there) and rejected inside stage/`INNER`/`INIT` blocks; it must be a finite ratio `>= 1`.
- **Search-space scaling, phase 1 (`SearchSpace`: one owner of the optimiser coordinate system).** Every OPTIM dimension now has a real box `[lo, hi]`, a per-line shape tag (`OPTIM <KEY> (i) <lo> <hi> [LIN | LOG | ASINH <c>]`, default `LIN`; `LOG` requires `lo > 0`, `ASINH c` is the C-infinity symlog for sign-crossing multi-decade dims) and a root-level policy `OPTIM_SCALE AUTO | NONE` (default `NONE` in this phase: optimisers keep iterating in raw OPTIM units, `ln` for LOG dims -- byte-identical to 1.4.x; `AUTO` maps every dimension to the unit box `[0,1]` so `STEP`, `XTOL_ABS` and `PARAM fd_step` mean the same fraction of every box). `LOG_HP <ratio>` keeps its meaning as the auto-LOG rule on untagged dims. `OptimizerSpec::low/high` are the INTERNAL bounds (derived by `bind_space()`), `in()/out()` map REAL<->INTERNAL through the space for both `std::vector` and dlib vectors (the old two templates indexed with `[]` vs `()`), every sub-spec including the previously skipped BASINSV2 EXPLORE/REFINE is bound, and the eight sites that hand-rolled `ln`/`exp` (ANNEAL and ASA starts, BASINSv2 EXPLORE, PRESTAGE widths, init strategies unit->real / WARM clamp / chain dedup, journal and pot-header tags) go through the space. `analyse_logscale()` survives as a test-only shim that builds an unnormalised space. The `SEARCH SPACE` journal section now prints the policy, the real width ratio, and one row per dimension (scale, box origin, real and internal bounds, start point in both spaces).
- **Basin pools store REAL-space parameters and measure distances in INTERNAL coordinates (`set_space`).** BasinPool v1 documented transformed-space params but received real top-K params and `exp()`'d them when re-seeding EXPLORE; BasinsV2 inserted a mix of transformed Sobol points and real refinement results -- both only correct with no log-scaled dim. Pool checkpoint sections gain `params_real` and `space_fingerprint`: a resume against changed OPTIM bounds/scales is refused with a delete-checkpoint hint (previously the stale `low/high` loaded silently), and a pre-transform checkpoint is accepted only when every dimension is linear.
- **`GRAD_STRATEGY ANALYTICAL/HYBRID` gradients are pulled back through the search space** (`g_u = dL/dtheta * dtheta/du`). The host's analytical gradient is taken in real parameters while the optimiser iterates in internal coordinates; under `LOG_HP` the analytical path silently disagreed with the finite-difference path by the factor `theta`. Masked-FD dimensions are unaffected (they already perturb internal coordinates).
- **Search-space scaling, phase 2 (per-dimension `STEP` for NLopt) -- BREAKING for configs that set `STEP` under `LIB NLOPT`.** `STEP` is now a dimensionless fraction of each OPTIM dimension's (transformed) width, `0 < STEP <= 0.5` (Powell's `XU-XL >= 2*RHOBEG`; NLopt's own default is 0.25), with the same meaning as the annealers' `PARAM STEP_FRAC`; `STEP <KEY>[(indices)] <fraction>` overrides it per key or per index (unknown key / non-OPTIM'd index are startup errors). NLopt receives one initial step per dimension (`set_initial_step(vector)`, `initial_step.h`), which restores BOBYQA/COBYLA's per-dimension coordinate rescaling that an identical scalar on every dim used to disable (`nlopt_compute_rescaling` returns all-ones), and which gives SBPLX/NELDERMEAD a first simplex proportionate to every box. Near-bound handling is per dimension: BOBYQA/COBYLA/NEWUOA_BOUND shrink only the tight dimension to `0.75*slack` (NLopt's default rule; the old guard shrank ONE scalar to half the slack of the single tightest dimension, starving every other -- on the run15 box one 8e-3-wide AMPGRIDMB dim set FIXWEIGHT(33)'s step to 2e-7 of its width), a start ON a bound is left alone, and SBPLX/NELDERMEAD point the first vertex inward when the start is within one step of the upper bound. With `STEP` unset NLopt's x-dependent heuristic is untouched. `hpo_run.log` prints the config-level `Initial step` and `Step consumption` lines in OPTIMISER and, once the start point is known, a per-dimension table (internal step, step/width, real step at the start, notes) with the vector actually handed to NLopt or read back from `nlopt::opt::get_initial_step(x, dx)`. Migration: the previous absolute meaning is reproduced exactly by per-key overrides (`STEP <KEY> <old_step / width_KEY>`; verified byte-identical on example 03). Example `03_nlopt_local` moves to `STEP 0.1` (its old `STEP 0.05` was 2.5 % of RCUT2B's width and 16.7 % of SGRIDMB's; a uniform 5 % is too timid for its 60-evaluation budget, reaching the same optimum only after ~200) and its fingerprint is regenerated.
- **Search-space scaling, phase 3 (backends in the unit box; the guards the [0,1] box needs).** `GRAD_STRATEGY NUMERICAL` gets an in-house central-difference kernel with `h_i = fd_step * max(|u_i|, 1)` -- in the unit box exactly `fd_step * width` on every dimension, and the same kernel HYBRID's masked pass uses -- as the default under `OPTIM_SCALE AUTO`; Ceres' `DynamicNumericDiffCostFunction` (per-parameter delta `max(sqrt(eps), fd_step*|u|)`, which collapses to 1.5e-8 next to every lower bound of the unit box) stays the default under `OPTIM_SCALE NONE` so legacy runs are byte-identical; `PARAM fd_kernel inhouse|ceres` overrides either way. `XTOL_ABS` reaches NLopt as a per-dimension vector, and SBPLX/NELDERMEAD configs that set only `XTOL_REL` get a HINT that the per-dim x-stop guard is relative to the coordinate's magnitude (vacuous next to a lower bound). The ANNEAL family's resolvable-step floor (`resolvable_coordinate_scale`) is floored at one machine epsilon of the interval width (the ULP of a coordinate at 0 is a subnormal). `DLIB:GFS` warns when dlib's own hidden ln transform (any dim with `lower > 0` and `upper/lower >= 1000` in the coordinates it receives, seeds NOT transformed accordingly) would fire -- impossible under `AUTO`, possible under `NONE`. `ASA:ASA` notes at startup which starting coordinates sit exactly at 0 (their lower bound under `AUTO`), where its `(1+Delta_X)*x` reanneal tangents are identically zero. New env override `TADAH_OPTIM_SCALE=AUTO|NONE` (the reference-suite gate runs every example both ways).
- **Search-space scaling, phase 4 -- `OPTIM_SCALE AUTO` is now the DEFAULT (BREAKING for every optimiser that is not width-invariant).** Every OPTIM dimension is mapped to the unit box before any backend sees it, so `STEP`, `XTOL_ABS` and `PARAM fd_step` mean the same fraction of every box and SBPLX's subspace partition, MLSL's clustering radius, GFS's trust sphere, BFGS/CERES line searches and ASA's reannealing all operate on commensurate coordinates. Width-invariant backends (ANNEAL family, GRID, RANDOM, CRS/ISRES/ESCH/DIRECT, BOBYQA/COBYLA without STEP) evaluate the same real points as before up to rounding; the reference suite shows 14 of 21 examples byte-identical under AUTO and 7 with changed trajectories (03 NLopt SBPLX in box units; 04/06/07/12 DLIB:BFGS; 08 DLIB:GFS; 21 ASA reannealing) -- three better, three within 0.2 %, and 04 (30-eval BFGS) 5.6 % worse through basin selection (at 4x the budget both policies converge, to different local optima; the NONE basin happens to be lower). Their fingerprints are regenerated. `OPTIM_SCALE NONE` (or `TADAH_OPTIM_SCALE=NONE`) reproduces every pre-1.5 trajectory byte-identically (verified 21/21) and remains for one release as the escape hatch.
- **Search-space scaling, phase 5 (seed-relative `AUTO` boxes, bound-occupancy audit, sidecar files).** `OPTIM <KEY> (indices) AUTO [RATIO <f> | FRAC <p>] [FLOOR <a>] [GROUP_FLOOR <r>] [LIN | LOG | ASINH <c>]` derives each selected index's box from its CONFIG seed: geometric `[x0/f, x0*f]` (mirrored for negative seeds; the default for positive-only keys, `RATIO 2`, using the same key table as the refit hpotarget writer so the two cannot disagree) or linear `x0 +/- max(p*|x0|, a, r*max|x0| over the line)` (`FRAC 0.5` default; `FRAC 0` with `FLOOR`/`GROUP_FLOOR` gives every index the same absolute half-width -- the natural box for grid centres, whose unit is the grid spacing rather than the value). Cutoff keys (`RCUT*`) are excluded (the neighbour list is sized from explicit high bounds); a zero seed under `RATIO`, a zero-width linear box and a non-positive `LOG` box are startup errors. `tadah analysis suggest_bounds` (data-driven ranges from descriptor metadata) is the complementary tool for descriptor shape keys; `AUTO` covers per-coefficient boxes (e.g. `FIXWEIGHT`) that only a seed can size -- the source of the within-key width spread the refit writer's group floor manufactures. Every run writes `hpo_search_space.tsv` (one row per dimension: label, key, OPTIM index, real bounds, origin, seed, scale, internal bounds) and, when any box was derived by `AUTO`, `hpo_optim_resolved.hpo` -- a paste-ready explicit `OPTIM` block that pins exactly the searched space. A generic **bound-occupancy audit** (every backend, replacing the mis-scaled `bound_hints`) marks the dimensions on which the running best sits within 2 % of an OPTIM limit in internal units (so LOG dims are judged in `ln`), keeps the eval since which each mark persists, and prints a milestone INFO table plus one HINT and a final `DIAGNOSTICS` table with the concrete remedy (widen that side, rerun `INIT METHOD WARM`); the run never changes OPTIM bounds by itself.
- **Review fixes to the per-dimension STEP plan** (adversarial review of phases 0-3): an `std::invalid_argument` from NLopt (a rejected setup such as BOBYQA's `insufficient space between the bounds`) was about to be classified as graceful self-termination because NLopt attaches its stop message to that exception too -- it is a FAILED run again; `STEP 0.5` on BOBYQA is capped just below width/2 (Powell's `width >= 2*rhobeg` check fails by one ulp at exactly 0.5 in BOBYQA's rescaled coordinates); the near-bound `0.75*slack` shrink applies to BOBYQA only (COBYLA treats bounds as constraints; NEWUOA/PRAXIS collapse the vector to `min|dx|`, so shrinking one dim would shrink every dim's radius); BASINS/BASINSV2 stage specs now carry `STEP <KEY>` overrides (they copied only the block-wide `STEP`); "overrides without a block-wide STEP must cover every dimension" is checked at startup (it fired only when the local stage started, after a PRESTAGE/MULTISTART budget was spent); an outer `STEP` next to INNER overrides warns; the journal's effective-step table prints MMA/CCSAQ's real default (`0.5*width`, not the derivative-free heuristic) and the INNER plan under MLSL/AUGLAG, and per-dimension near-bound/inward/capped adjustments are journaled as WARNINGs also on overridden dimensions.
- **`PARAM GRID_POINTS <n>` (TADAH:GRID, integer `>= 2`, default 20)** replaces the `STEP <n>` point-count overload: `STEP < 1` truncated to zero points and looped forever at the low corner, `STEP 1` divided by zero (NaN coordinates). `STEP` under GRID is now a hard error pointing at `GRID_POINTS`; the help text advertised a `PARAM SPACING` that nothing read. Example `11_grid_sweep` updated (same lattice, fingerprint unchanged).
- **`LIB ASA / ALGO ASA` — Lester Ingber's Adaptive Simulated Annealing (ASA-30.53), vendored under `external/asa` (BSD-3-Clause).** The full runtime option surface keeps the ORIGINAL ASA spellings as `PARAM` keys (`Limit_Acceptances`, `Temperature_Ratio_Scale`, `Reanneal_Parameters`, quenching via `User_Quench_Param_Scale[/i]`, the `Queue_Size` evaluation cache, `Multi_Number` multi-minima tracking, …), with per-dimension indexed forms (`PARAM User_Quench_Param_Scale[3] 0.7`) and hard errors on unknown or compiled-out names. Generic `MAXEVAL`/`MAXTIME`/`STOPVAL`/`SEED`/`THREADS` are honoured (`FTOL/XTOL` rejected in favour of ASA's own `Cost_Precision`×`Maximum_Cost_Repeat` plateau). ASA's block-parallel design (`PARAM Gener_Block N`) evaluates each generated block concurrently on a `min(THREADS, Gener_Block_Max)`-wide pool through the upstream-designated spawn region; results are THREADS-invariant and `Gener_Block 1` (default) is proven bit-identical to unmodified serial ASA by a golden unit test against a pristine all-gates-off reference build. Three fenced `TADAH-PATCH` hunks (hook include + spawn-region hook + an upstream infinite-loop fix in the parallel invalid-state retry loop) are inventoried in `external/asa/TADAH-PATCHES.md`. Single-instance semantics (one `asa()` per process; strategy wrappers run sequentially and work unchanged); ASA's own journal goes to `asa_out<rank><run>`. Documented deviations from upstream defaults: `Curvature_0 1` (upstream `0` costs O(dim²) exit evaluations) and `Multi_Specify 1`. Example `21_asa` + fingerprint; docs page `asa.rst` in Tadah.MLIP.
- **ASA run diagnostics (post-first-live-run).** The exit summary reports live `generated=`/`accepted=` totals next to upstream's restored at-best counters (which read `0/0` whenever the best never left the seed); a `P_TEMP_TOO_SMALL` stop names the underflowed dimension by its OPTIM label (`[dim 42: CGRID2B[10]]`); and block evaluations stamp the live acceptance temperature on journal tags (`[slot i/N Tcost=…]`, also appended to the `ASA gen= acc=` progress line) so temperature-schedule pathologies — every one of the first three live runs — are visible in real time. Backed by two additional plain-store mirrors in the fenced asa.c patches (`tadah_asa_exit_index`, `tadah_asa_cost_temp`); the golden-neutrality gate stays green. `HPOLog::set_eval_slot` gains an optional temperature label, and a NaN temperature now omits the `T=` field from tags.
- **`PARAM SWAP_WINDOW` for `ANNEAL_PT`** controls the number of epochs in each windowed per-pair swap-acceptance table (default `20`); `0` disables windowed tables and retains cumulative reporting only.
- **`PC_SCRIPT_TIMEOUT` keyword — self-describing name for the per-`pc_script` wall-clock limit (formerly the root `MAXTIME`).** `MAXTIME` is kept as a working legacy alias so every existing `.hpo` keeps parsing; both feed the same per-script LAMMPS `timer timeout` (SECONDS), and if both appear the later line wins (a WARNING is emitted). This disambiguates the chronic confusion with the *OPTIMIZER-block* `MAXTIME` (a genuine whole-run wall-clock stop, unchanged) and with `PC_WORKER_TIMEOUT` (the outer per-worker-task hard deadline). A new startup diagnostic line now reports the effective per-script limit, which keyword supplied it, and the effective hard per-worker-task deadline — none of which had any startup diagnostic before.
- **Near-bound floor-step audit in the journal (ANNEAL family, CORANA only).** After every rung (serial), epoch (ANNEAL_PT), or T-step (ANNEAL_PA), the driver marks dimensions that are within one floor-step of an OPTIM bound while Corana `V[i]` is already at `V_FLOOR_FRAC*width`. This is a heuristic observation: inward proposals remain possible and the mark does not prove that the optimum lies outside the box. Milestone summaries report the bound, gap, floor, marked chains, and persistence so sustained occupancy can be inspected as possible bound pressure. The audit is enabled for single-process runs only; multi-rank PT/PA skip it because no global mark union is implemented.
- **Annealing boundary policy is explicit:** `PARAM BOUNDARY_MODE 0` (default) performs mirror reflection without a fixed fold-count cap (tested across finite-double extremes on the audited x86-64 platform); `1` redraws each offending coordinate as in Corana et al. Discarded redraws do not consume host-evaluation budget.
- **Live cross-rank global-best checkpoint.** Every process-local improvement competes synchronously for canonical `best_pot.tadah` under a cross-process lock; candidates use deterministic `(loss, rank, slot, eval)` ordering and a winning complete potential is flushed and atomically renamed into place. A confirmed fresh run discards an unrelated prior incumbent, while an explicit checkpoint resume retains and validates its canonical winner. MPI rank-local potentials use `best_pot.tadah.r<rank>` on every rank, including rank 0. A SIGKILL before rename can leave a hidden unique temporary file, which readers and later publishers safely ignore.

### Changed
- **`tadah hpo` help and the Sphinx key tables print the TOKEN a key accepts, not its internal sentinel.** Keys that carry their `AUTO`/`OFF` sentinel as the numeric default used to advertise `(default 0)` for a value the parser then rejects; both renderers now print `(default AUTO)` / `(default OFF)` and list the accepted tokens next to the numeric range.
- **Dimension labels carry the OPTIM index (1-based) -- BREAKING for scripts that parse `KEY[i]`.** Every label the run prints (`hpo_run.log` tables, `params.tadah`/`best_params.tadah` headers, `hpo_step_scales.tsv`, `hpo_search_space.tsv`, pot headers) is now `KEY[n]` with `n` the index the `OPTIM` line uses: the 1-based position among the key's numeric values, or for `FIXWEIGHT` the model weight named in `FIXINDEX`. It used to be the 0-based config-token position (`AMPGRIDMB[0]` for `OPTIM AMPGRIDMB (1)`, `WATOM[2]` for a pair-triple weight), an implementation detail. One label builder (`HPOTargets::build_search_space`) now feeds the host, the journal and the sidecars; the host's three duplicate builders (params.tadah header, NaN-clamp parameter dump, bound hints) are gone. Reference fingerprints regenerated on the current build (hyperparameter keys renamed for the FIXWEIGHT examples; values refreshed within the stored tolerances).
- **`ASA:ASA` per-dimension `PARAM Name[i]` indices are 1-based -- BREAKING for ASA configs that use the indexed form.** The six per-dimension ASA options (`User_Quench_Param_Scale`, `User_Temperature_Ratio`, `User_Delta_Parameter`, `User_Parameter_Temperature`, `Multi_Grid`, `Queue_Resolution`) numbered dimensions from 0 while every dimension number the run prints -- the `dim` column of `hpo_search_space.tsv`, the `#` column of the journal's `SEARCH SPACE` table -- starts at 1, so `PARAM User_Quench_Param_Scale[1] 0.7` silently applied to the dimension listed as `2`. The index now means the printed dimension number. Migration: add one to every index (old `[k]` meant the dimension printed as `k+1`). `[0]` is a hard error naming the change; `[1]`..`[D-1]` still parse and now address the dimension one EARLIER than before, so check such configs against `hpo_search_space.tsv`. `ASA stopped: P_TEMP_TOO_SMALL [dim N: LABEL]` counts from 1 for the same reason. No example or workspace config used the indexed form, so no fingerprint changes.
- **`tadah hpo` no longer prints the per-key `Config Key / Label / Index / Params / H bound / L bound` table (nor `Cannot create label for: ...`) to stdout.** The information lives in `hpo_search_space.tsv` and the `SEARCH SPACE` section of the journal; the descriptor-label machinery behind the table (`Opti::labels`, `create_labels` and helpers) is removed.
- **`hpo_search_space.tsv` layout.** Columns `key` and `optim_index` are dropped (the label carries both); a `#` comment header explains every column, including `version` (the search-space revision: 1 for the boxes parsed from the config, to be incremented only by a future bound-adaptation step); values use 10 significant digits; every column is space-padded to one width and the columns are tab-separated, so the file is aligned for reading and still a TSV (strip whitespace when parsing).
- **`STEP` is rejected where it was silently ignored** (DLIB:GFS, TADAH:RANDOM, NLopt algorithms that never read an initial step, STRATEGY-level STEP under BASINS) and under TADAH:GRID (use `PARAM GRID_POINTS`). Configs carrying such a `STEP` fail at startup with the backend's hint.
- **OPTIM lines are parsed with a strict grammar** `OPTIM <KEY> (indices) <low> <high>`: stray tokens between the key and the bounds were silently dropped (the parser popped the bounds from the end of the line); they are now a hard error naming the line. The `INNER` unknown-key message lists the full driver-attribute vocabulary from one shared table (it omitted `MAXTIME`/`STOPVAL`/`XTOL_*`/`GRAD_STRATEGY`).
- `hpo_run.log` / `HPOTargets`: the flattened OPTIM labels are built by the `HPOTargets` constructor (same `KEY`/`KEY[i]` scheme) so startup diagnostics can name dimensions.
- **Bump-support gate relaxed to per-candidate enforcement (`BUMPGATE CANDIDATE`, the new default); the 1.4.0 startup box-corner hard-error is now opt-in via `BUMPGATE STRICT`.** On a hard **Cut_Dummy** bump channel, startup now hard-errors only when (a) the SEED pot's own bumps spill past their stated cutoff (unchanged, legacy pots stay rejected) or (b) an OPTIM box contains **no feasible point** (`c_lo + w/eta_hi > RCUT`). A partially infeasible box is accepted at full width: an INFO line announces the armed per-candidate gate, and every sampled combination violating `c + w/eta <= RCUT` (against the candidate's own sampled RCUT when OPTIM'd) is rejected in `HPO_Host::operator()` **before any training work** with a graded band-D failure (measure = summed overhang / half-width, so the annealer keeps a downhill slope back to feasibility; `FAILSCORE_GRADING OFF` returns the flat `FAILSCORE`). This removes the forced box shrinkage that degenerated near-cutoff Blip/Blip5 bumps into spikes. Configs that pass the STRICT gate arm nothing and evaluate byte-identically. Note rejects consume `MAXEVAL` iteration slots (at near-zero wall cost — no training/LAMMPS) — size `MAXEVAL` accordingly or budget by `MAXTIME`; the SUMMARY failure census gains `bumpgate=N` and the RESULT trailer a reject line. Env override `TADAH_BUMPGATE=CANDIDATE|STRICT`. The NN list needs no bump-side padding either way (RCUT stays authoritative; sizing covers OPTIM RCUT high bounds). Gradient paths fall back to FD when the previous evaluation was a gate reject (stale trainer-cache guard).
- **PC_LAMMPS scripts now execute through LAMMPS's native `Input::file()` reader — backward `jump`/`label`/`next` loops (and `if … then "jump SELF <label>"`) work with full LAMMPS semantics.** The previous executor fed preprocessed lines one at a time to `Input::one()` on the cached instance, where a backward jump cannot rewind (`rewind(infile)` is a no-op on stdin in library mode); the sticky label search then silently swallowed the remainder of the script AND leaked into the instance's next eval, where the raw-text EXTERN hook bound an uninitialized potential — a SIGSEGV storm across every worker slot the moment a config referenced a rolled loop script (run26, `eos_dilute_fast2.in`). Each per-slot cache entry now owns the script rendered once to a node-local temp file (`ScriptFile`; zero per-eval I/O), and the potential handoff moved from the per-line hook to a per-thread staging slot consumed by `PairTadah::coeff()` (`stage_extern`, Tadah.LAMMPS). The `vector<string>` `run_script` overloads remain as per-call-render wrappers. The FD/gradient path runs the same executor via lazily-rendered `LammpsSim::script_file()`.
- **Per-section soft-timeout semantics are preserved under the file executor by an injected boundary guard.** `Input::file()` never checks the timer between commands and `clear` destroys a fired `Timer`, so a timed-out section would silently roll into the next section with a fresh budget and the sim would misreport OK. `prep_script_lines` now injects `if "$(timeremain) == 0.0" then "<sentinel>"` before every mid-script `clear` that follows a timer-armed section that created a simulation box (`create_box`/`read_data`/`read_restart` — `$(...)` cannot be evaluated before a box exists, and a boxless section has no run/minimize so its timer can never fire); a fired timer aborts the run at the section boundary (classified `TIMEOUT_ABORT`, band B as before). A timeout in the final section remains the clean `is_timeout()` path (`TIMEOUT_CLEAN`, instance kept).
- **Cached LAMMPS instances are invalidated after exception failures.** An exception leaves `Input::file()` without its internal cleanup (open FILE handle, nested-file counter capped at 16 levels, possibly a sticky label search), so the entry is erased after the failvar readback and rebuilt on the next task (~free: create is ~0.02% of run cost). Timeout-clean failures keep the healthy instance exactly as before. This also removes the two latent null-derefs of the old raw-text EXTERN hook (unchecked `dynamic_cast`, `load()` failure ignored).
- **`ANNEAL_PT` adaptive-ladder guardrails (D26) — behavior change for `LADDER_ADAPT=1` configs.** New `PARAM LADDER_MIN_GAP` (default `0.1`, `0` = off, must be `[0,1)`) floors every interior log-gap at that fraction of the mean gap via clamp-and-redistribute waterfilling: pairs whose acceptance is *gap-insensitive* (e.g. basin-offset-limited — run24 drove adjacent-rung ratios to 1.006–1.010 this way, en route to the documented D21 degenerate-pair failure where equal rungs exchange unconditionally) can no longer be contracted to the 1-ULP representability guard. Floored pairs are flagged in the update journal line (`floor-clamped=n/(K-1)`) and in a new trailing `at_floor` column of `hpo_temperature_ladder.tsv`. Additionally the controller now **freezes itself once equalized** (revised after adversarial review): per-pair acceptance evidence is **pooled across consecutive settled windows** — zero-information windows (all pairs exactly 0%/100%, e.g. an equal-loss plateau, which the original per-window streak would have latched on permanently) are held without advancing or destroying the evidence, an unsettled pooled test resets it, and the freeze fires only when every pair is within 2 binomial sigma of the pooled mean (or floor-held below it) on ≥100 pooled attempts/pair, where the test resolves ~±9 acceptance points. New `PARAM LADDER_FREEZE` (default `1`) disables it; note the freeze can stop adaptation even under `LADDER_ADAPT_UPDATES 0` ("no update-count cap"), which remains the hard cap. Endpoints, determinism, MPI aggregation, and eval counts are unchanged; `LADDER_MIN_GAP 0` restores the previous unbounded contraction.
- **`ANNEAL_PT` CLASSIC diagonal-RAM trust region (D27) — behavior change for `STEP_ADAPT_EVERY>0` configs.** New `PARAM STEP_TRUST_FACTOR` (default `64`, `0` = off, must be `>1`) clamps each dimension's adapted sigma to within that factor of the slot's post-warm-up calibrated baseline. The RAM's centred shape term is a mean-zero random walk with **no restoring force** and only a 1-ULP floor (`V_FLOOR_FRAC` is Corana-only), so per-dim sigma could drift arbitrarily far from its calibrated scale — run24 held dims at sigma/width ≈ 2e-10 for 70k epochs. The baseline encodes legitimate per-dim sensitivity (deliberately tiny sigmas on hypersensitive wide-box dims stay tiny); the clamp only bounds *drift*, and the representability floor/support cap still apply last so a coordinate can always move. The key is a hard error anywhere the RAM cannot run (CORANA, explicit `STEP`, `STEP_AUTO 0`, `STEP_ADAPT_EVERY 0`). Journal: the sigma/width block's `(last N epochs)` label is corrected to `(instantaneous V; …)` — the printed values were always the live per-slot V at print time, not a window aggregate — and a new `sigma dims at trust bound per slot (lo|hi of D)` grid reports pinned dims; the per-slot step-health window counters are no longer accumulated where nothing reads them (CORANA / `STEP_ADAPT_EVERY=0`).
- **`ANNEAL_PT` step warm-up: bracket-convergence acceptance and sensitivity classification (D28).** A coordinate that exhausts its attempt budget with a two-sided bisection bracket tightened to `upper <= 4x lower` now finishes **`bracket-ok`** at the bracket's geometric mean (within 2x of both edges, each measured on the wrong side of the acceptance band) instead of `unconverged` — run24 finished 949/2784 (34%) of its (slot,dim) calibrations "unconverged/unexplained" under the old two-consecutive-in-band rule, whose 4-sample batches cannot reliably certify. The remaining unconverged dims are classified when the best tested batch names the cause: **`insensitive`** (best alpha ~ 1 at every tested scale — the objective does not respond to the coordinate) or **`hypersensitive`** (best alpha ~ 0 — acceptance collapses at every tested scale), with an actionable HINT (drop/fix the dim; narrow or log-scale the OPTIM range). The calibration summary line now reads `ok= bracket-ok= … unconverged=N (insensitive= hypersensitive= unexplained=)`, and "unexplained" means genuinely unexplained. Status bits are appended (existing TSV/MPI encodings unchanged); behaviour change is limited to previously-misbehaving dims, which enter production at the bracket midpoint instead of the best-tested batch scale.
- **`ANNEAL_PT` reporting: time-aware new-best table, final swap window, epoch-line T (D29).** The end-of-run `new-best count per slot` table is cumulative since process start, so a run's initial transient fossilizes in it (run24's hot-slot counts all dated from the first ~500 of 20,457 bests and read as steady-state oscillation); a companion `last new best per slot (eval #; 0 = never)` table now separates "still contributing" from "transient fossil". The final summary also repeats the **last completed `SWAP_WINDOW` per-pair acceptance table** (falling back to a labelled partial window) next to the cumulative one, which averages late drift away — run24's bottleneck pairs ran at 1–3% in the final windows while the cumulative row still read 11–22%. The per-epoch `T=[...]` on the epoch line is now snapshotted at epoch start, i.e. the temperatures the epoch's rungs actually ran at, not the post-ladder-adapt/post-RT-cooling values. Table renderers are extracted to testable `pt_detail::format_slot_count_table` / `format_pair_table` helpers. Post-review corrections: with `SWAP_WINDOW 0` (cumulative-only mode) the window counters are no longer accumulated and no window table is printed — previously the final summary could relabel whole-run counters as a "partial window"; when no window ever completed, the fallback table is labelled with its true coverage (`no completed SWAP_WINDOW; covers epochs 1-N`); and `bracket-ok` calibration rows keep `coord_sigma` at the scale their acceptance/alpha measurements were actually taken (the best tested batch), preserving the D9 measured-at-coord_sigma TSV contract while production still seeds from the bracket midpoint.
- **Adaptive, power-shaped `ANNEAL_PT` temperature ladders.** `LADDER_POWER` shapes the initial normalized log ladder (`1` remains geometric); opt-in `LADDER_ADAPT` uses independent MPI-aggregated pair windows and diminishing stochastic approximation to equalize adjacent swap rates while preserving the cold/hot endpoints, cooling trajectory, slot-resident state, deterministic budgets, and objective-call count. Gain/cadence/freeze controls are validated strictly, each update is journaled and written to `hpo_temperature_ladder.tsv`, and fixed endpoints plus `REPLICAS` remain the controls on absolute acceptance.
- The annealing-defaults benchmark report now distinguishes matched from unequal-seed cells and preserves the raw conclusions: NS20/NT2/P0.05 median 0.59 beat matched NS5/NT2 median 1.41, no NS20/NT5 42-D cell was run, and the six-seed PACCEPT medians were not monotone (P0.20 0.33 versus P0.10 0.42).
- Journal SUMMARY lines report BOTH `wall=<ms>/eval (<N> ev/s)` — true wall-clock throughput over the window since the previous milestone, i.e. what the run delivers under the current parallelisation — and `latency=<ms>/eval` (was `avg=`), the mean per-evaluation wall time on its worker thread. When K evaluations are fully concurrent (ANNEAL_PT/PA, DLIB:GFS), latency can approach K× the wall cost and must not be read as throughput. The end-of-run PERFORMANCE section gains a `Wall per eval` line and relabels the latency mean accordingly.
- **ANNEAL-family validation is fail-fast.** `STEP_FRAC` must be finite and in `(0,1]`; `V_FLOOR_FRAC` is `[0,1]` with zero explicitly disabling the floor; count knobs must be integral; bounds must have finite `low < high` and finite width; explicit `T_MIN` must not exceed resolved `T_HOT`/T0; and all numeric knobs must be finite. CONFIG/INIT seeds require the exact transformed dimension, finite values, and membership in every transformed OPTIM interval. `L` under Corana, Corana adjustment knobs under classic, and `RESET_TO_BEST` under PA are rejected instead of ignored. So are explicit controls whose values would be discarded: `STEP` with `STEP_FRAC`; `T_HOT` with `T0_PROBES`/`T0_PACCEPT`; `REANNEAL=0` with `REANNEAL_SCALE`; PT `T_COLD` with `LADDER_SPAN`; and static PT (`RT=1`) with `T_MIN`. An empty log-scale mask is valid all-linear input; if a width-derived step underflows on a subnormal interval, the diagnostic requests an explicit positive `STEP`.
- Corana step vectors are clamped to `[V_FLOOR_FRAC*width, width]` at initialisation and adjustment, and incomplete `NS` cycles are not adapted. Progress lines report floor/cap saturation counts. `RESET_TO_BEST` remains active for serial/PT and is attributed to step 7 of the original Corana algorithm (also used by Brommer).
- `THREADS` is the total per-rank shared-pool width for PC_LAMMPS fan-out and MLIP train/predict; it does not multiply `OMP_NUM_THREADS`, which now controls only residual OpenMP kernels.

### Fixed

Both fingerprint tools ignore the `SLOT` bookkeeping column (it had been recorded as a loss component and a hyperparameter since the column was added). ANNEAL_PA likewise rejects an unrepresentable population-state payload in that prologue.

Help, banners, comments, and tests now state the existing PT/PA `INIT_MODE 0` distinction: non-seed jitter remains Gaussian in both variants, using the CLASSIC sigma or the numeric initial Corana `V` as its standard deviation.

Previously the shared feasibility check rejected that entire band, flattening the graded failure landscape and defeating downhill repair in classic ANNEAL, Corana, PT, and PA. T0 calibration and PA feasibility weighting/resampling deliberately retain the stricter `< 0.999*FAILSCORE` feasibility rule.

### Changed

- **ANNEAL auto-T0 calibration rewritten** (was: mean pairwise |ΔE| over uniform-box probes — on real FAILSCORE-cliff landscapes it collapsed to `T0=1.0` (all probes fail) or `T0~1e16` (mixed), producing a stone-cold or never-cooling schedule). Now: the seed point is evaluated first, `T0_PROBES` sigma-scaled local probes are drawn around it from a dedicated RNG stream, and `T0 = median(uphill feasible-probe ΔE)/ln(1/T0_PACCEPT)` over feasible probes (loss < 0.999*FAILSCORE; the graded band remains excluded); if feasible probes contain no uphill move, the scale falls back to the median absolute feasible delta. A non-finite or failure-band seed triggers one uniform-box batch and re-anchors on the best feasible point; a landscape with no feasible probe is a hard error with remediation hints. `FAILSCORE` is plumbed into `OptimizerSpec::failscore` for this.

The previous rule watched the monotone best-so-far, so it force-stopped after exactly `NEPS` rungs once the best stalled — even while the chain was productively exploring at high T.
- **ANNEAL `T_MIN` default is now `auto = T0 * 1e-6`** (~132 rungs at the shipped RT 0.90; was fixed `1e-12`, ~170+ rungs — budget-limited runs always died on MAXEVAL instead of reaching any convergence criterion). Explicit `PARAM T_MIN` unchanged.

The only 42-D NS20 cell was NT2/P0.05: its 0.59 median beat the matched NS5/NT2 median 1.41; no NS20/NT5 cell was run. Among the six-seed NS5/NT5 cells, PACCEPT was not monotone (P0.20 median 0.33 versus P0.10 median 0.42), while P0.05 had median 8.2e-3. ### Added
- **`LIB TADAH ALGO ANNEAL_PT` — parallel tempering (replica exchange)** over the shared annealing core. K replicas (`PARAM REPLICAS`, default `max(THREADS,2)`) run the classic or Corana stepper concurrently at a fixed geometric temperature ladder (`T_COLD..T_HOT`, slot 0 coldest; `T_HOT` auto-calibrated, `T_COLD = T_HOT/LADDER_SPAN`); adjacent pairs attempt Metropolis state swaps every `SWAP_EVERY` epochs with deterministic even/odd (DEO) pairing. Swaps move states `(x, f)`, not temperatures — the Corana step vector V stays with its slot. `PARAM RT < 1` turns the static ladder into a PT→SA cooling hybrid (ends at `T_MIN`). Cumulative per-pair swap acceptance is journaled, with windowed tables every `SWAP_WINDOW` epochs (default 20; 0 disables windows); 20–40% is a literature-derived starting heuristic, while measured ladder flow is the outcome diagnostic. Execution: persistent `std::thread` worker pool (`THREADS`, ships in every build including `TADAH_ENABLE_OPENMP=OFF`) over the one thread-safe `HPO_Host`; with `REPLICAS` fixed, a deterministic objective, and no timing-dependent stop, the same SEED gives the same evaluated set for any THREADS (per-replica RNG streams, per-pair swap-coin streams, deterministic budget slicing).
- **`LIB TADAH ALGO ANNEAL_PA` — population annealing** over the shared core. `POPULATION` walkers (default `4×THREADS`, min 16) anneal from `T_HOT` to `T_MIN`; each temperature step reweights by `exp(-Δβ·f)`, resamples (systematic resampling — one RNG draw, lowest variance; non-finite/failure-band walkers (including finite graded failures) receive zero weight when at least one feasible walker exists; an all-failed population skips resampling and continues geometric cooling), then runs `SWEEPS` rungs per walker. Adaptive schedule via `PARAM ESS_TARGET` (default 0.5): largest Δβ keeping ESS at target × feasible population, capped by `RT` per step; `ESS_TARGET 0` = pure geometric. Walker state `(x, f, V)` copies on resample; with `POPULATION` fixed, a deterministic objective, and no timing-dependent stop, per-slot RNG streams keep the evaluated set THREADS-invariant. Per-step journal line: T, ESS, unique parents, culled, finite fraction, population best.
- **`TADAH_HPO_MPI` CMake option (default OFF)** — distributes ANNEAL_PT replicas / ANNEAL_PA walkers over MPI ranks (contiguous slot blocks; rank 0 runs the T0 calibration and broadcasts; PT boundary pairs exchange via `MPI_Sendrecv` with both sides drawing the same per-pair coin; PA resampling is decided on rank 0 from the gathered population). Deliberately narrow: no ScaLAPACK, no `MPI_Trainer`, no binary rename — MPI appears only in `hpo_mpi.h` and the two parallel drivers; training stays rank-local and every rank's LAMMPS instances run on `MPI_COMM_SELF` (requires an MPI LAMMPS library — configure-time check — and `MPI_THREAD_MULTIPLE`; on Cray MPICH set `MPICH_MAX_THREAD_SAFETY=multiple`). Mutually exclusive with the legacy `TADAH_BUILD_MPI`. Fixed-name outputs gain a `.r<rank>` suffix on ranks > 0; at run end rank 0 re-evaluates the global best once so its `best_*.tadah` files carry the global winner. MAXEVAL is enforced globally (allreduced accounting + deterministic slicing), and the global REPLICAS/POPULATION count must be at least the MPI rank count.
- Examples: `18_anneal_pt`, `19_anneal_pa`, `20_anneal_corana` (the serial adaptive variant had no example).
- **`PARAM REANNEAL 0|1` (default 1) + `PARAM REANNEAL_SCALE` (default 0.25)** — when a schedule cools out (`T < T_MIN`) with budget left, the chain snaps to the best-so-far and repeats from `REANNEAL_SCALE^n * T0` only while that start can execute at least two rungs before crossing `T_MIN`; budget, time, STOPVAL, or plateau may stop it earlier (run15 lever: the fixed schedule truncated progress mid-improvement). ## [1.2.0] and earlier (condensed)

The `v1.0.0` → `v1.1.1` releases were the "internal playground" era. HPO began life as a small NLOpt wrapper; releases in this period focused on build-system iteration so that HPO could co-build with LAMMPS (CMake + traditional make), `FAIL_SCORE` defaulting, the move to `PC_<type>` performance counters, and a sequence of small fixes. No published changelog covers this era; treat anything before `1.3.0-beta.1` as undocumented in the modern sense.
