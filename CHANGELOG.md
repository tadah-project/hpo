# Changelog

All notable changes to **Tadah.HPO** (hyper-parameter optimisation) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **`OPTIM MPARAMS` is checked against the model's function at startup** (`Function_Base::mparams()`, Tadah.MODELS): `OPTIM MPARAMS (i)` is refused on a function that reads fewer than i values (`BF_Linear`, `BF_Polynomial2`, `Kern_Linear`, `Kern_Quadratic` and `Kern_LQ` read none: the search changed nothing), on an integer value (`MPARAMS (1)` of `Kern_Polynomial`, the degree; a candidate was truncated) and, for a value that must be positive (`Kern_RBF`'s sigma), on a box whose low bound is not > 0. Test: `test_optim_key_rules.cpp`.
- **`OPTIM` on a value its key takes only as an integer, or on an internal key, is refused at its line.** A value every format (blueprint `value_type`) of the key gives `INT` or `UINT` (`SBASIS`; a candidate such as 14.47 was trained as 14): `OPTIM SBASIS (1) is not a valid search target: value 1 of SBASIS is an integer (SBASIS takes UINT), ...`; `OPTIM OALGO (1)` keeps its own message. An internal key (`DSIZE`, `RCUT2BMAX`, `ESTDEV`, ..., computed by tadah; `OPTIM ESTDEV` failed every evaluation with "Attempt to add internal key"): `OPTIM ESTDEV is not a valid search target: ESTDEV is an internal key ...`. Test: `test_optim_key_rules.cpp`.
- **`OPTIM RCUT2B` / `RCUTMB` on a cutoff that a descriptor takes from its setfl file is refused at startup** (`D_Base::cutoff_fixed_by`, Tadah.MODELS): the cutoff of D2_EAM and DM_EAM, also D2_EAM's or DM_EAM's own value inside a D2_mJoin or DM_mJoin (the other joined descriptors' values stay searchable): `OPTIM RCUT2B (1) is not a valid search target: D2_EAM takes the cutoff 5.58190742024 of its setfl file 'Ta.eam.alloy' (SETFL) and refuses another value, so every candidate but the -c value would fail; leave RCUT2B (1) out of OPTIM.` These descriptors refuse a cutoff other than the file's (Tadah.MODELS 1.6.0), so such a search scored only its `-c` value: every other candidate failed its evaluation (FAILSCORE, the journal line "D2_EAM: RCUT2B ... differs from the cutoff ... of the setfl file") and the run ended with status 0. Before this release's per-evaluation trainer, a thread's reused trainer did not build its D2_EAM again, so that check did not run past the thread's first evaluation, and `best_pot.tadah` recorded a candidate cutoff that `tadah predict` refuses. Test: `test_optim_key_rules.cpp`.
- `shutdown_script_executor()` (`script_executor.h`): stops the script executor, joining its workers; `IterHealthRecord::layout_matches`, `n_weights` and `layout_cols`: whether the column layout describes the weights (as many columns as weights), and both counts.

### Changed
- `init_script_executor(width)` builds the script executor of `width` workers in place of the one there is (it stored a width that only the first `script_executor()` call of the process read); `script_executor()` builds a one-worker executor at its first use outside a run, as before. `detail::script_executor_width()` is gone. The journal's `ScriptExecutor: <n> workers` line and its fan-out width are the executor's own width.

### Removed
- The environment variable `TADAH_HPO_FORCE_REBUILD`: every evaluation builds its model (see Fixed), which is what it asked for.

### Fixed
- **Every evaluation trains a model built from its own candidate.** `HPO_Host` builds a `Trainer` from the candidate context (the `-c` configuration with the candidate's `OPTIM` values) for every evaluation. A thread used to keep the `Trainer` of its first evaluation, rewrite only the `OPTIM` keys of its context and call `Trainer::reinit()` (MLIP), which re-applied the descriptor parameters only, so whatever the model, its kernel or basis function and its design matrix read when they were built kept the first evaluation's value, and what a fit wrote into the context stayed for the next. Consequences, now gone:
  - `OPTIM EWEIGHT`, `FWEIGHT` and `SWEIGHT` (the design matrix's row weights, every model) were not applied after a thread's first evaluation: every later evaluation trained the first one's weights, while the potentials recorded the candidate's values;
  - `OPTIM MPARAMS` (the kernel of M_KRR) kept the first value, while every potential recorded the candidate's: a `best_pot.tadah` predicted otherwise than the loss it was reported with;
  - `OALGO 3` potentials gained one `SIGMA` per evaluation of a thread (10, 20, 30 values for 3 weights), and `tadah predict --error` on such a `best_pot.tadah` corrupted the heap (Tadah.MODELS also fixes the append itself);
  - an M_KRR `-c` potential with `WEIGHTS` failed the first evaluation of each thread ("This object is already trained!"; Tadah.MODELS fixes the flag; every evaluation would fail now that each builds its model);
  - a second run in one process (a task file with two `TASK hpo` blocks) trained the first run's model, with the first run's `LAMBDA`, `FWEIGHT`, `FORCE` and every other key it does not search (and started its `PC_LAMMPS --hotvar` values where the first run ended: see below).
  The per-thread slot keeps the trainer of the thread's latest evaluation for `analytical_gradient` and the observables, stamped with its host: `analytical_gradient` of a host whose evaluation did not build the slot's trainer routes every parameter to finite differences (it differentiated another host's model). Building a `Trainer` costs little against a fit (0.023 ms against 0.40 ms for D2_BP with 3 functions on 80 atoms with forces); the setfl file of D2_EAM and DM_EAM is parsed once while its contents are unchanged, and the descriptors' configuration warnings are logged once per process (Tadah.MODELS). With `VERBOSE` > 0 the line a kernel prints when it is built (`Kern_RBF | sigma: ...`, and those of `Kern_Polynomial`, `Kern_Sigmoid`, `Kern_Quadratic` and `Kern_LQ`) now appears once per evaluation, where it appeared once per thread: a `Kern_RBF` run of 4 evaluations prints it 5 times (the startup check builds the model once), against 2. Other searches give the losses they gave (a search over a setfl cutoff now stops at startup, see Added): of the 27 reference examples, 24 write a byte-identical `loss.tadah`, `18_anneal_pt` and `19_anneal_pa` the same rows in another completion order (their concurrent replicas), and `13_restart` the same evaluations up to its restart, whose unseeded start point differs from run to run. With `LAMBDA -1` the evidence approximation starts every evaluation from the configured `ALPHA` and `BETA`, not from the previous evaluation's. Potentials from earlier runs that searched `EWEIGHT`, `FWEIGHT`, `SWEIGHT` or `MPARAMS` report an optimum that was never applied: re-run those searches. Tests: `test_hpo_fresh_trainer_e2e.cpp` (CTest `hpo_trainer_e2e`), Tadah.MLIP's `Task file: a second TASK hpo evaluates its own configuration`.
- **Every run starts its `PC_LAMMPS --hotvar` values from their declared initial value, or from WARM's seed.** The per-chain cache of the values each evaluation hands to the next (`warmstart_cache.h`) is cleared when a run starts (`HPO_Host::prepare_best_publication`, `warmstart::reset_for_fresh_run`); it lived as long as the process, so the second run of a task file with two `TASK hpo` blocks started each hot script from the value the first run's last evaluation converged to, and did not reproduce the same run made alone (example `01_minimal` at `MAXEVAL 3`, `DIGITS 15`: `TOTAL_LOSS/N` 1.043183703093665e-01 against 1.043183703095260e-01; now the second run's `loss.tadah`, `outvar.tadah` and `best_pot.tadah` are those of the run alone, under `PC_ISOLATION THREAD` and `PROCESS`). WARM's seeds, primed before the run, are kept. The evaluation counter still continues across runs, so the second run's `ITERATION` numbers and `DUMP` names follow the first run's (4-6 after a run of 3). Tests: `test_hpo_host_e2e.cpp` (`A second run in the same process starts its --hotvar values from their declared start or the WARM seed`), `test_hpo_pc_readback_e2e.cpp` (CTest `hpo_hotvar_e2e`).
- **The per-evaluation health monitor (`HEALTH_LOG`) checks the weights of every evaluation.** It read the column layout of `Trainer::dm` (Tadah.MLIP), which nothing builds -- M_BLR and M_KRR fit their own design matrix, and the fast path of a `FIXINDEX` that pins every weight builds none -- and skipped an empty layout, so it never recorded an evaluation: none of its warnings, the NaN/Inf one included, was printed since it was added. `HPO_Host` now passes the weights the model holds (fitted, or provisioned from `FIXWEIGHT`) and the layout `DesignMatrix::build` gives the model's design matrix, `fb->phi_layout(dc.layout())` (bias, D2 and DM blocks for `BF_Linear` and `Kern_Linear`; one block over all columns for a non-linear function, a kernel's over its basis vectors). Defects of the monitor that its first records showed:
  - `compute_iter_health` checked for NaN/Inf only the weights inside the layout's blocks; it checks every weight;
  - a layout with more columns than weights was taken for NaN/Inf weights (a sentinel) and the block it could not read for a block of zero weights; a layout that does not describe the weights is reported as such, `iter_health: eval <n> -- the model has <N> weights but its column layout has <M> columns: the per-block checks are skipped.`, rate-limited like the other warnings, and the per-block checks are skipped;
  - `IterHealthMonitor` changed its maps without a lock (its header asked callers to funnel records through one thread), while `HPO_Host`'s evaluations record concurrently (`ANNEAL_PT`/`ANNEAL_PA` replicas, `DLIB:GFS` batches): it is thread-safe (8 threads recording 400 records each counted 2730 to 3021 of the 3200 warnings).
  The warnings are printed on standard output (core Logger at WARNING), not in `hpo_run.log`. The `DM-skip fast path` test checked that `Trainer::dm` had an empty layout, which held for every evaluation; it checks that no MLIP parallel loop runs over the training structures on the fast path (one does when a weight is fitted). Tests: `test_iter_health.cpp` (a non-finite weight outside the blocks, a layout that does not describe the weights, concurrent records), `test_hpo_fixweight_e2e.cpp` (`[fixweight_e2e]`: the fast path and a fit with a block of zero weights, a fit whose weights are not finite).
- **Every run has worker pools of its own and stops them however it ends** (`RunPools`, `hpo.cpp`). `hpo_run()` builds the script executor of the run's `THREADS` and installs MLIP's parallel backend where it sizes its pools; on every way out -- a return, a signal stop, an error, also one at startup after the pools were built -- it removes the backend, stops the `PC_ISOLATION PROCESS` worker processes and joins the executor's workers, whose thread-local `PC_ISOLATION THREAD` LAMMPS instances and potentials end with them (they did at process exit). Before:
  - a run that threw (at startup after the worker processes were spawned, or an error `drive_run()` rethrows) left them running until process exit, so the next `hpo_run()` of the process failed `pc_worker_pool_init: pool already initialized` (a program that calls `hpo_run()` again; a task file stops at its first failed task);
  - the executor was a function-local static built at its first use, so every later run of the process (a task file with two `TASK hpo` blocks) ran on the first run's `THREADS` while its journal reported its own, and under `PC_ISOLATION THREAD` a script of the same name and line options ran on the LAMMPS instance the first run had cached; under `PC_ISOLATION PROCESS` a later run with a smaller `THREADS` handed tasks to worker ids its pool did not have (`PcWorkerPool::execute: bad slot`: in each of 8 runs of the test every evaluation failed, `STOPPED -- no evaluation produced a usable loss`);
  - MLIP's parallel backend outlived the run, so a later task of the process (`TASK train` after `TASK hpo`) ran its kernels on the HPO pool instead of OpenMP.
  The evaluation counter still carries over (the second run's `ITERATION` numbers continue the first's). Tests: `test_hpo_termination.cpp` (two runs in one process: the first failing after its worker processes started; `THREADS` 2 then 3; `THREADS` 3 then 1 under `PROCESS`), `test_script_executor.cpp` (`init_script_executor` gives the executor the width it asks for).

- `test_strict_parse.cpp`: the text `core::format_roundtrip` writes for every zero or normal double (the bounds of `hpo_optim_resolved.hpo`, the hpotargets `tadah refit` writes) reads back through the hpotarget number grammar (`parse_number`) bit for bit. - **Transient filesystem errors are retried before a write fails.** On
  network filesystems a lock, write, fsync or rename can fail for a moment
  (EBUSY, EAGAIN, ESTALE, ETXTBSY, EIO, ENOLCK, ETIMEDOUT, EDEADLK; EACCES
  only when the directory is on a network filesystem -- on a local disk it
  is a permission error and fails at once) and succeed when repeated. The
  durable best potential retries its whole lock → read → compare → replace
  transaction with exponential backoff (10 ms doubling to 2 s, ±20 %
  jitter), releasing its locks between attempts, until 30 s have passed
  since the first failure (the failing calls' own time counts; a call that
  blocks by itself can add its duration at either end). A retry that finds
  its own earlier rename in place (the directory fsync failed, or an NFS
  rename reported ENOENT after landing) completes that commit. Other
  permanent errors (ENOSPC, EROFS, ENOENT, ...) are not retried. The
  per-evaluation logs (`loss.tadah`, `outvar.tadah`, `params.tadah`,
  `stats.tadah` and their `best_*` twins), whose write errors were never
  checked, are appended one batch per writer drain
  (`io::RetryingAppendFile`): a failed batch -- a partial write included --
  is truncated back and rewritten, with ONE 10 s budget per drain shared by
  every file and `DUMP`/`BDUMP` archive (each still makes its own attempt,
  plus one immediate re-attempt after a permanent errno). A batch that
  still fails is dropped whole and reported with the rows lost, and that
  file gets single attempts until a write succeeds (repeats summarised, an
  INFO line when writes resume); the run goes on. Archives are written
  whole or not at all. After a shutdown signal retrying goes on for at most
  2 s (`BackoffPolicy::stop_grace`, per durable publication and per drain),
  so one blip after a scheduler's time-limit warning does not lose the
  in-flight best or the last rows. Every retry is a WARNING; DIAGNOSTICS
  gains `Transient I/O retries : N (best-potential a, per-eval
  logs/archives b); rows lost c; archives lost d` only when one of them is
  non-zero, so clean runs write byte-identical journals and files. New API:
  `durable_best::SysError` (errno, operation, path, `may_have_landed()`),
  `durable_best::Options` with `default_backoff()` and 4-argument overloads
  (the 3-argument forms keep the default policy), `io::BackoffPolicy`,
  `io::retry`. Test-only knobs: `TADAH_HPO_TEST_IO_FAULT="site,ERRNO
  [,skip=K][,count=N|always][,partial=B][,land][,latency=MS][;...]"` and
  `TADAH_HPO_TEST_IO_BACKOFF_MS="initial,cap,budget[,jitter]"`
  (`io::testing::ScopedFaults` in-process); with no faults installed an I/O
  call costs one relaxed atomic load. Tests: `test_durable_best.cpp`,
  `test_append_log.cpp`, `[durable_e2e]` in `test_hpo_fixweight_e2e.cpp`.
- **Density gates `RHOGATE` and `RHOBARGATE`** (root keys; `rho_gates.h` / `rho_gates.cpp`), for a model whose many-body term is a bare DM_REAM (DM_mJoin is refused). Both reject a candidate before training, right after its context is built and before any MPI traffic, as a graded band-D failure with the `BUMPGATE` bookkeeping (evaluation number, rows, stagnation, `record_fail_band`; `DUMP` potential header-only).
  - `RHOGATE <tol> [R_LO <r>] [NPTS <n>] [SEED ERROR|WARN]` (`RHOFORM SIGNED` only; the positive forms guarantee rho >= 0): scans rho_raw(r) = f_c sum a_n psi_n with `ReamDensity::scan_grid` on NPTS points (default 20001) of [R_LO, RCUTMB] (default R_LO = 0.15 RCUTMB) and fails when rho_min < -tol rho_max, with v = min(1e8, v_peak + v_int) (the worst dip plus its mean depth, relative to rho_max).
  - `RHOBARGATE <bcc|fcc|hcp> <a0> <f_lo> <f_hi> [NPTS <n>] [SEED ERROR|WARN]` (every form): fails when the monatomic lattice density rhobar(a) = sum_s m_s rho_raw(d_s a) is not strictly decreasing on a = a0 [f_lo, f_hi] (NPTS points, default 1001; shells enumerated once for the largest reachable RCUTMB), with v = min(1e8, sum of the rises / max |rhobar|); a flat step fails at v = 0.
  - Saturated measures (DBL_MAX, the top of band D): a non-finite density, rho_max <= 0 or rhobar = 0, a pair weight <= 0, an empty window. A density DM_REAM would refuse gets no verdict (it fails in training as before).
  - Strict grammar: the numbers follow the number grammar of every hpotarget key (`strict_parse.h`: `tol`, `R_LO`, `a0`, `f_lo` and `f_hi` are single finite decimal tokens, so no hexadecimal float, inf, nan or subnormal; `NPTS` an integer in decimal digits, so no sign, fraction or exponent; errors name the line); keywords and values case-insensitive, duplicates, unknown or repeated keywords and missing values refused; no environment override. Startup checks (`validate_hpo_setup`): the bare DM_REAM, `RHOGATE` under `SIGNED` only, `R_LO` and the first `RHOBARGATE` shell inside the smallest reachable RCUTMB (knot-aware).
  - Arming: a gate is evaluated per candidate, its pair weights included; it is armed by an OPTIM line (in any case, anywhere in the file) on `AMPGRIDMB`, `CGRIDMB`, `SGRIDMB` or `RCUTMB` (`HPOTargets::density_gate_keys`). A gate without one cannot act (every candidate has the `-c` density and its one verdict; an OPTIM `WATOM` only scales it) and is an error at its line naming those keys (owner decision 2026-09-29; it was accepted with a "not armed" INFO line and the `-c` verdict reused). A pair weight no candidate can make positive is a startup error under either SEED mode.
  - Seeds: the `-c` potential and every CONFIG/WARM point of the resolved INIT chains and of an active RESTART block's METHOD chain (`RestartSpec::seed_points`; `RESTART WARM <file>` in the messages) are evaluated as candidates at startup; `SEED ERROR` (default) stops the run with one message naming every failing seed, `SEED WARN` warns. One INFO state line per gate.

- **Every optimiser records why its search ended, and the run's trailer says so: `COMPLETED` is no longer written.** The TADAH (`RANDOM`, `GRID`, `ANNEAL`, `ANNEAL_PT`, `ANNEAL_PA`), DLIB (`GFS`, `BFGS`) and CERES drivers record `<LIB>:<ALGO>: <reason>` with a fixed reason (`run_end.h`, *Added*: `MAXEVAL reached`, `MAXTIME exceeded`, `STOPVAL reached`, `FTOL_ABS reached`, `FTOL_REL reached`, `XTOL_REL reached`, `tol_gradinf reached`, `max_iter reached`, `T_MIN reached`, `FTOL plateau`, `all grid points evaluated`, `no optimisable dimensions`); the journal's stop line gives the numbers, a tolerance's value with `(default)` when its key was not set (`DLIB:BFGS stopped: FTOL_ABS reached after 51 evaluation(s): the loss changed by less than FTOL_ABS = 1e-07 (default) from one iteration to the next`). A Ceres ending without such a reason is named by Ceres' termination type and the head of its message, a fixed text too (below). NLopt keeps its result strings, ASA `ASA: <reason>`, a gradient that is not finite its own status and `RESTART` its stagnation status. Before, these drivers recorded none for most endings and `HPOLog::finish` wrote `COMPLETED`: `DLIB:BFGS` for a spent `MAXEVAL` (its only line was `DLIB:BFGS -- MAXEVAL=N reached; preserving best-so-far`, which stays its stop line) and for its convergence test, which left no line at all; `DLIB:GFS`, `TADAH:RANDOM` and `TADAH:GRID` for a spent `MAXEVAL` and the whole grid; the annealers for every stop, `STOPVAL` and `MAXTIME` included; the CERES drivers for every ending but a rejected gradient's, a `FAILURE` such as `STEEPEST_DESCENT`'s `Numerical failure in line search` included.   - `TADAH:ANNEAL`, `ANNEAL_PT`, `ANNEAL_PA`: from their stop line, on every MPI rank: `MAXEVAL reached` (also during the T0 probes, or before any proposal), `MAXTIME exceeded` (also during the probes), `STOPVAL reached` (also on a probe), `T_MIN reached`, `FTOL plateau` (the plateau and `ANNEAL_PT`'s best-stall rule), `no optimisable dimensions`; a signal records none (`SHUTDOWN`). ## [1.5.0] — 2026-09-10

### Breaking

Three changes require config or script edits. Each has an exact migration.

1. **`PARAM` values use the `ON` / `OFF` / `AUTO` vocabulary; numeric booleans
   and `0`-means-disabled are gone.** Every OPTIMIZER-block key that took `0`/`1`
   as a flag (`CORANA`, `RESET_TO_BEST`, `REANNEAL`, `LADDER_ADAPT`,
   `LADDER_FREEZE`) now takes `ON`/`OFF`, and every key where `0` used to mean
   "off" or "derive it yourself" (`SWAP_WINDOW`, `LADDER_MIN_GAP`,
   `STEP_TRUST_FACTOR`, `ESS_TARGET`, `INIT_JITTER_MAXEVAL`, `CHAIN_LENGTH`,
   `NT`, `REPLICAS`, …) takes `OFF` or `AUTO`. `BOUNDARY_MODE` became the enum
   `REFLECT` | `REDRAW`. The motivation was that `0` had come to mean three
   different things across neighbouring keys — `INIT_JITTER_MAXEVAL 0` meant
   AUTO while `INIT_JITTER_LADDER 0` would have meant OFF — which no amount of
   documentation makes readable in a config file. *Migration:* the old spelling
   is a hard error naming the new token, so nothing fails silently; run your
   config once and follow the messages. `PARAM CORANA 1` → `PARAM CORANA ON`,
   `PARAM SWAP_WINDOW 0` → `PARAM SWAP_WINDOW OFF`, `PARAM BOUNDARY_MODE 1` →
   `PARAM BOUNDARY_MODE REDRAW`.
2. **Every index a person reads is 1-based, in files as well as the journal.**
   Ladder slots, exchange pairs, walker lineages and pc-worker slots print from
   1 in `hpo_run.log`, in the TSV sidecars, and in `best_pot.tadah`'s
   `# HPO_SOURCE_SLOT` header. Internally these indices stay 0-based — they
   round-trip as identities through the warm-start cache and the resume
   checkpoint — so the conversion happens at the I/O boundary and the readers
   shift back by one. *Migration:* a script that parses a slot number from a
   Tadah file must subtract 1; a checkpoint written by 1.4.x still resumes
   (its header is read with the old radix).
3. **`ANNEAL_PT` scales the initial jitter along the ladder by default**
   (`PARAM INIT_JITTER_LADDER AUTO`, see below). This changes the starting
   population of every existing PT run at a fixed `SEED`. *Migration:*
   `PARAM INIT_JITTER_LADDER OFF` reproduces the 1.4.x placement exactly
   (verified byte-for-byte across the 600-cell performance matrix).

### Added
- **`PARAM INIT_MODE JITTER` no longer borrows `STEP_FRAC` for the initial displacement (`ANNEAL_PT`, `ANNEAL_PA`).** `JITTER` used the production step scale as its jitter sigma, so a run that wanted large proposals on a narrow temperature ladder had no way to say so without also scattering its replicas across the whole OPTIM box: at 816 dimensions and `STEP_FRAC 0.15` a "jittered" replica was 37 % of a full randomisation from the seed, which is not a warm start. `INIT_MODE` now takes a magnitude of its own in one of three forms. `JITTER` (unchanged default) keeps the `STEP_FRAC` coupling and the Gaussian draw. **`JITTER <fraction>`** sets sigma as that fraction of each OPTIM width. **`JITTER AUTO <p>`** MEASURES it: for every dimension the calibration finds the largest displacement whose loss stays inside `|L(sigma_d) - L0| <= p*|L0|`, by a two-sign screen at the per-side cap followed by a log-bisection, using the run's own `--hpotarget` objective. `FIXED` and `AUTO` draw uniformly on `+/-sigma` rather than from a Gaussian, because their sigma is a declared or measured BOUND and a Gaussian puts ~32 % of coordinates outside it. The calibration does **not** consume `MAXEVAL` (a `probe::Scope` marks the phase and the host exempts it, so no stagnation counter, restart policy or `durable_best` publication sees these evaluations either); it is bounded instead by `INIT_JITTER_MAXEVAL` (`AUTO` = the protocol's own worst case) and `INIT_JITTER_MAXTIME_FRAC` (0.25 of `MAXTIME`). Progress, a per-dimension sigma table (`hpo_init_jitter.tsv`), a per-status census and the resulting per-rung initial loss are journaled. Two cost levers for large search spaces: `INIT_JITTER_SAMPLE <n>` measures only `n` dimensions, chosen round-robin across parameter families, and lets the rest inherit their family's median sigma/width (measured on an 816-dimension space: 2 888 probes full, 256 at `SAMPLE 64`, an 11x lever), and `INIT_JITTER_AUDIT <n>` (default 32) re-probes sampled dimensions at `sigma/2`, since sigma is a grid certificate rather than a proof that the loss is monotone in displacement. Under MPI the dimensions are split into contiguous per-rank blocks and the sigma vector is broadcast, so every rank seeds from the same measurement.
- **`PARAM INIT_JITTER_LADDER` — per-slot scaling of the initial jitter (`ANNEAL_PT`), `AUTO` by default.** Slot `k` is displaced by `sigma_k = sigma_d * (T_k/T_HOT)^gamma`. Without it every non-seed slot was placed with the SAME displacement, so the coldest replica — whose job is to refine the seed — started as far from it as the hottest explorer, and a warm start survived only at slot 1. `AUTO` resolves to `gamma = 0.5`, which is equipartition (the equilibrium coordinate spread in a locally quadratic basin goes as `sqrt(T)`) and deliberately NOT a function of `LADDER_SPAN`: the span already enters through `T_k/T_HOT`, so making gamma depend on it too would count the same quantity twice. Scaled sigmas are floored at `resolvable_coordinate_scale` so a wide ladder cannot collapse the cold slots onto the seed, and the clamped count is journaled with a warning. `OFF` restores the 1.4.x placement; a number sets gamma directly. **Measured:** on a warm start (`ellipsoid6`, `LADDER_SPAN 1e6`, seed at 2 % of the default start) the default is 4x better on median best and wins 38 of 40 paired seeds. It is not a universal win — `rosenbrock6` from a MEDIOCRE seed at the same span is 1.22x worse on 40 of 40 seeds, because a curved valley reached from a poor starting point is exactly where you want the cold slots to spread out and hunt. That is what `OFF` is for.
- **Per-dimension Corana acceptance census (`ANNEAL_PT`) + `hpo_corana_acceptance.tsv`.** Corana's step adaptation was always per dimension (`adjust_corana_step` reads that coordinate's own accept/propose counts), but the journal only ever printed one rung-wide acceptance per epoch, so a run could sit at a healthy 30 % while hundreds of coordinates never moved and nothing said so. The counters that drive the adaptation could not be read after the fact either — they are an evidence window that is consumed and zeroed every `NS` sweeps — so `ChainState` now carries a never-reset parallel copy. The journal reports a median-acceptance and frozen-dimension grid at the `SWAP_WINDOW` cadence, and at end of run a per-slot percentile table (nearest-rank over the visited dimensions), the named extremes at the two ends of the ladder, and a HINT listing coordinates Corana accepted no move on at ANY temperature. The full per-`(slot, dimension)` table, with each slot's adapted `sigma` next to the acceptance it produced, goes to `hpo_corana_acceptance.tsv` (gathered across MPI ranks). Rows are per SLOT, not per walker: an exchange moves `x`/`f` between slots and leaves `V` and these counters behind — stated wherever a row is printed.
- **Multi-token `PARAM` values.** `PARAM` accepts a value list (`PARAM INIT_MODE JITTER AUTO 0.05`) under a per-key grammar rather than a maximum arity, because the two callers frame their input differently — `HPOTargets::read` is line-framed while `tadah refit`'s inline `OPTIMIZER` block is a flat token stream, where a greedy read would silently swallow the following block. An unexpected extra token is a hard error naming the key and the token.

- **`GRAD_STRATEGY ANALYTICAL/HYBRID` gradients are pulled back through the search space** (`g_u = dL/dtheta * dtheta/du`). The host's analytical gradient is taken in real parameters while the optimiser iterates in internal coordinates; under `LOG_HP` the analytical path silently disagreed with the finite-difference path by the factor `theta`. Masked-FD dimensions are unaffected (they already perturb internal coordinates).

- **Near-bound floor-step audit in the journal (ANNEAL family, CORANA only).** After every rung (serial), epoch (ANNEAL_PT), or T-step (ANNEAL_PA), the driver marks dimensions that are within one floor-step of an OPTIM bound while Corana `V[i]` is already at `V_FLOOR_FRAC*width`. This is a heuristic observation: inward proposals remain possible and the mark does not prove that the optimum lies outside the box. Milestone summaries report the bound, gap, floor, marked chains, and persistence so sustained occupancy can be inspected as possible bound pressure. The audit is enabled for single-process runs only; multi-rank PT/PA skip it because no global mark union is implemented.
- **Annealing boundary policy is explicit:** `PARAM BOUNDARY_MODE 0` (default) performs mirror reflection without a fixed fold-count cap (tested across finite-double extremes on the audited x86-64 platform); `1` redraws each offending coordinate as in Corana et al. Discarded redraws do not consume host-evaluation budget.
- **Live cross-rank global-best checkpoint.** Every process-local improvement competes synchronously for canonical `best_pot.tadah` under a cross-process lock; candidates use deterministic `(loss, rank, slot, eval)` ordering and a winning complete potential is flushed and atomically renamed into place. A confirmed fresh run discards an unrelated prior incumbent, while an explicit checkpoint resume retains and validates its canonical winner. MPI rank-local potentials use `best_pot.tadah.r<rank>` on every rank, including rank 0. A SIGKILL before rename can leave a hidden unique temporary file, which readers and later publishers safely ignore.

- **`ANNEAL_PT` adaptive-ladder guardrails (D26) — behavior change for `LADDER_ADAPT=1` configs.** New `PARAM LADDER_MIN_GAP` (default `0.1`, `0` = off, must be `[0,1)`) floors every interior log-gap at that fraction of the mean gap via clamp-and-redistribute waterfilling: pairs whose acceptance is *gap-insensitive* (e.g. basin-offset-limited — run24 drove adjacent-rung ratios to 1.006–1.010 this way, en route to the documented D21 degenerate-pair failure where equal rungs exchange unconditionally) can no longer be contracted to the 1-ULP representability guard. Floored pairs are flagged in the update journal line (`floor-clamped=n/(K-1)`) and in a new trailing `at_floor` column of `hpo_temperature_ladder.tsv`. Additionally the controller now **freezes itself once equalized** (revised after adversarial review): per-pair acceptance evidence is **pooled across consecutive settled windows** — zero-information windows (all pairs exactly 0%/100%, e.g. an equal-loss plateau, which the original per-window streak would have latched on permanently) are held without advancing or destroying the evidence, an unsettled pooled test resets it, and the freeze fires only when every pair is within 2 binomial sigma of the pooled mean (or floor-held below it) on ≥100 pooled attempts/pair, where the test resolves ~±9 acceptance points. New `PARAM LADDER_FREEZE` (default `1`) disables it; note the freeze can stop adaptation even under `LADDER_ADAPT_UPDATES 0` ("no update-count cap"), which remains the hard cap. Endpoints, determinism, MPI aggregation, and eval counts are unchanged; `LADDER_MIN_GAP 0` restores the previous unbounded contraction.
- **`ANNEAL_PT` CLASSIC diagonal-RAM trust region (D27) — behavior change for `STEP_ADAPT_EVERY>0` configs.** New `PARAM STEP_TRUST_FACTOR` (default `64`, `0` = off, must be `>1`) clamps each dimension's adapted sigma to within that factor of the slot's post-warm-up calibrated baseline. The RAM's centred shape term is a mean-zero random walk with **no restoring force** and only a 1-ULP floor (`V_FLOOR_FRAC` is Corana-only), so per-dim sigma could drift arbitrarily far from its calibrated scale — run24 held dims at sigma/width ≈ 2e-10 for 70k epochs. The baseline encodes legitimate per-dim sensitivity (deliberately tiny sigmas on hypersensitive wide-box dims stay tiny); the clamp only bounds *drift*, and the representability floor/support cap still apply last so a coordinate can always move. The key is a hard error anywhere the RAM cannot run (CORANA, explicit `STEP`, `STEP_AUTO 0`, `STEP_ADAPT_EVERY 0`). Journal: the sigma/width block's `(last N epochs)` label is corrected to `(instantaneous V; …)` — the printed values were always the live per-slot V at print time, not a window aggregate — and a new `sigma dims at trust bound per slot (lo|hi of D)` grid reports pinned dims; the per-slot step-health window counters are no longer accumulated where nothing reads them (CORANA / `STEP_ADAPT_EVERY=0`).
- **`ANNEAL_PT` step warm-up: bracket-convergence acceptance and sensitivity classification (D28).** A coordinate that exhausts its attempt budget with a two-sided bisection bracket tightened to `upper <= 4x lower` now finishes **`bracket-ok`** at the bracket's geometric mean (within 2x of both edges, each measured on the wrong side of the acceptance band) instead of `unconverged` — run24 finished 949/2784 (34%) of its (slot,dim) calibrations "unconverged/unexplained" under the old two-consecutive-in-band rule, whose 4-sample batches cannot reliably certify. The remaining unconverged dims are classified when the best tested batch names the cause: **`insensitive`** (best alpha ~ 1 at every tested scale — the objective does not respond to the coordinate) or **`hypersensitive`** (best alpha ~ 0 — acceptance collapses at every tested scale), with an actionable HINT (drop/fix the dim; narrow or log-scale the OPTIM range). The calibration summary line now reads `ok= bracket-ok= … unconverged=N (insensitive= hypersensitive= unexplained=)`, and "unexplained" means genuinely unexplained. Status bits are appended (existing TSV/MPI encodings unchanged); behaviour change is limited to previously-misbehaving dims, which enter production at the bracket midpoint instead of the best-tested batch scale.
- **`ANNEAL_PT` reporting: time-aware new-best table, final swap window, epoch-line T (D29).** The end-of-run `new-best count per slot` table is cumulative since process start, so a run's initial transient fossilizes in it (run24's hot-slot counts all dated from the first ~500 of 20,457 bests and read as steady-state oscillation); a companion `last new best per slot (eval #; 0 = never)` table now separates "still contributing" from "transient fossil". The final summary also repeats the **last completed `SWAP_WINDOW` per-pair acceptance table** (falling back to a labelled partial window) next to the cumulative one, which averages late drift away — run24's bottleneck pairs ran at 1–3% in the final windows while the cumulative row still read 11–22%. The per-epoch `T=[...]` on the epoch line is now snapshotted at epoch start, i.e. the temperatures the epoch's rungs actually ran at, not the post-ladder-adapt/post-RT-cooling values. Table renderers are extracted to testable `pt_detail::format_slot_count_table` / `format_pair_table` helpers. Post-review corrections: with `SWAP_WINDOW 0` (cumulative-only mode) the window counters are no longer accumulated and no window table is printed — previously the final summary could relabel whole-run counters as a "partial window"; when no window ever completed, the fallback table is labelled with its true coverage (`no completed SWAP_WINDOW; covers epochs 1-N`); and `bracket-ok` calibration rows keep `coord_sigma` at the scale their acceptance/alpha measurements were actually taken (the best tested batch), preserving the D9 measured-at-coord_sigma TSV contract while production still seeds from the bracket midpoint.
- **Adaptive, power-shaped `ANNEAL_PT` temperature ladders.** `LADDER_POWER` shapes the initial normalized log ladder (`1` remains geometric); opt-in `LADDER_ADAPT` uses independent MPI-aggregated pair windows and diminishing stochastic approximation to equalize adjacent swap rates while preserving the cold/hot endpoints, cooling trajectory, slot-resident state, deterministic budgets, and objective-call count. Gain/cadence/freeze controls are validated strictly, each update is journaled and written to `hpo_temperature_ladder.tsv`, and fixed endpoints plus `REPLICAS` remain the controls on absolute acceptance.

The end-of-run PERFORMANCE section gains a `Wall per eval` line and relabels the latency mean accordingly.

### Changed
- **BREAKING — bump-support gate at `tadah hpo` startup (was warn-only).** For a compact bump channel (D2_Blip/D2_Blip5, DM_REAM bump density) under a hard **Cut_Dummy** cutoff, startup now HARD-ERRORS when (a) the seed pot's own bumps or (b) any OPTIM box corner (`CGRID` high bound + `SGRID` low bound) let a support `c + w/eta` reach past RCUT — a truncated overhang is an energy/force STEP at the cutoff (measured 139 meV/atom on a real Ta run whose OPTIM boxes permitted it, with 11/32 blips pushed past RCUT). Every violation is listed with the exact bound that fixes it; when RCUT itself is OPTIM'd the gate binds against its LOW bound. A non-finite or failure-band seed triggers one uniform-box batch and re-anchors on the best feasible point; a landscape with no feasible probe is a hard error with remediation hints. `FAILSCORE` is plumbed into `OptimizerSpec::failscore` for this.

The only 42-D NS20 cell was NT2/P0.05: its 0.59 median beat the matched NS5/NT2 median 1.41; no NS20/NT5 cell was run. Among the six-seed NS5/NT5 cells, PACCEPT was not monotone (P0.20 median 0.33 versus P0.10 median 0.42), while P0.05 had median 8.2e-3. These measurements motivated a starting default, not a workload-independent ranking.
- ANNEAL RNG streams are now decorrelated per consumer (chain proposals vs T0 probes) via salted `seed_seq` streams: toggling `T_HOT`/probe settings no longer shifts the proposal sequence for a given SEED, and cross-config comparisons stay aligned.
- `MULTISTART` now decorrelates per-start seeds (`seed + start_index`; was: every start reused the same SEED, so stochastic inner optimisers produced near-duplicate chains). The per-start seed is journaled.
- ANNEAL-family progress lines show `current/total` (`rung=4/57`, `epoch=3/23`, `step=2/12`): the total is the planned maximum — whichever of the T_MIN schedule or the remaining MAXEVAL budget binds first (plateau/STOPVAL may still end the run earlier; REANNEAL cycles update the total). Unbounded runs (pure-PT ladder with no MAXEVAL) keep a plain counter.

### Added
- **`LIB TADAH ALGO ANNEAL_PT` — parallel tempering (replica exchange)** over the shared annealing core. K replicas (`PARAM REPLICAS`, default `max(THREADS,2)`) run the classic or Corana stepper concurrently at a fixed geometric temperature ladder (`T_COLD..T_HOT`, slot 0 coldest; `T_HOT` auto-calibrated, `T_COLD = T_HOT/LADDER_SPAN`); adjacent pairs attempt Metropolis state swaps every `SWAP_EVERY` epochs with deterministic even/odd (DEO) pairing. Swaps move states `(x, f)`, not temperatures — the Corana step vector V stays with its slot. `PARAM RT < 1` turns the static ladder into a PT→SA cooling hybrid (ends at `T_MIN`). Cumulative per-pair swap acceptance is journaled, with windowed tables every `SWAP_WINDOW` epochs (default 20; 0 disables windows); 20–40% is a literature-derived starting heuristic, while measured ladder flow is the outcome diagnostic. Execution: persistent `std::thread` worker pool (`THREADS`, ships in every build including `TADAH_ENABLE_OPENMP=OFF`) over the one thread-safe `HPO_Host`; with `REPLICAS` fixed, a deterministic objective, and no timing-dependent stop, the same SEED gives the same evaluated set for any THREADS (per-replica RNG streams, per-pair swap-coin streams, deterministic budget slicing).
- **`LIB TADAH ALGO ANNEAL_PA` — population annealing** over the shared core. `POPULATION` walkers (default `4×THREADS`, min 16) anneal from `T_HOT` to `T_MIN`; each temperature step reweights by `exp(-Δβ·f)`, resamples (systematic resampling — one RNG draw, lowest variance; non-finite/failure-band walkers (including finite graded failures) receive zero weight when at least one feasible walker exists; an all-failed population skips resampling and continues geometric cooling), then runs `SWEEPS` rungs per walker. Adaptive schedule via `PARAM ESS_TARGET` (default 0.5): largest Δβ keeping ESS at target × feasible population, capped by `RT` per step; `ESS_TARGET 0` = pure geometric. Walker state `(x, f, V)` copies on resample; with `POPULATION` fixed, a deterministic objective, and no timing-dependent stop, per-slot RNG streams keep the evaluated set THREADS-invariant. Per-step journal line: T, ESS, unique parents, culled, finite fraction, population best.
- **`TADAH_HPO_MPI` CMake option (default OFF)** — distributes ANNEAL_PT replicas / ANNEAL_PA walkers over MPI ranks (contiguous slot blocks; rank 0 runs the T0 calibration and broadcasts; PT boundary pairs exchange via `MPI_Sendrecv` with both sides drawing the same per-pair coin; PA resampling is decided on rank 0 from the gathered population). Deliberately narrow: no ScaLAPACK, no `MPI_Trainer`, no binary rename — MPI appears only in `hpo_mpi.h` and the two parallel drivers; training stays rank-local and every rank's LAMMPS instances run on `MPI_COMM_SELF` (requires an MPI LAMMPS library — configure-time check — and `MPI_THREAD_MULTIPLE`; on Cray MPICH set `MPICH_MAX_THREAD_SAFETY=multiple`). Mutually exclusive with the legacy `TADAH_BUILD_MPI`. Fixed-name outputs gain a `.r<rank>` suffix on ranks > 0; at run end rank 0 re-evaluates the global best once so its `best_*.tadah` files carry the global winner. MAXEVAL is enforced globally (allreduced accounting + deterministic slicing), and the global REPLICAS/POPULATION count must be at least the MPI rank count.
- Examples: `18_anneal_pt`, `19_anneal_pa`, `20_anneal_corana` (the serial adaptive variant had no example).
- **`PARAM REANNEAL 0|1` (default 1) + `PARAM REANNEAL_SCALE` (default 0.25)** — when a schedule cools out (`T < T_MIN`) with budget left, the chain snaps to the best-so-far and repeats from `REANNEAL_SCALE^n * T0` only while that start can execute at least two rungs before crossing `T_MIN`; budget, time, STOPVAL, or plateau may stop it earlier (run15 lever: the fixed schedule truncated progress mid-improvement). Re-anneal count reported in the summary and stop line.
- `anneal_core.h` — host-independent building blocks shared by the ANNEAL family (knob parsing/validation with per-algo whitelists, Corana §4 plateau tracker, robust T0 estimator, mirror reflection, salted RNG streams), unit-tested directly in `test_anneal_core.cpp`.
- ANNEAL warns when SEED is set only inside the INIT block (it seeds the init strategy, not the annealer's proposal stream).

### Fixed
- **WARM init: a missing or unparseable seed file is now unconditionally FATAL**, independent of `WARM_ON_MISMATCH` (which governs seed-CONTENT mismatches only: missing parameters, out-of-box clamping). Previously the default `warn` policy printed one stderr line, returned an empty init, and the annealer silently started from the OPTIM box CENTRE instead of the seed — invisible in the journal and masked whenever the OPTIM boxes are centred on the seed values.
- ANNEAL dead knobs are now hard errors instead of silent no-ops: `XTOL_REL`/`XTOL_ABS`, `VECTOR_ARR`, `GRAD_STRATEGY`, unknown `PARAM` keys (typo guard), and `THREADS`/`POPULATION` on the serial annealer (pointing at `TADAH:ANNEAL_PT` / `TADAH:ANNEAL_PA`).
- `PARAM L` is no longer validated (or read) under `CORANA 1` — it is a classic-variant knob.
- ANNEAL best-so-far bookkeeping: `best_x` now always pairs with `best_f` (previously a T0 probe could lower `best_f` while `best_x` stayed at the seed, handing `RESET_TO_BEST` an inconsistent state).
- Example fingerprint tools: repeated hyperparameter column names (e.g. `OPTIM FIXWEIGHT (2-4)` → three `FIXWEIGHT` columns) are now disambiguated as `NAME[k]` consistently in BOTH `generate_fingerprint.py` and `compare_fingerprint.py`. Previously the generator's dict collapsed duplicates (last column won) while the comparator matched the FIRST column — any flat-direction move in a duplicated column then masqueraded as a regression (bit example 17). Fingerprints for examples 16/17 regenerated.
- PC_LAMMPS: the host now builds ONE candidate-potential object per (thread, evaluation) and shares it across every `clear`/`pair_coeff EXTERN` cycle of every script that thread runs (`LammpsRunner::run_script` shared-potential overload; was a full `LammpsTadah` reconstruction per `pair_coeff` — 75x per evaluation on run15-class setups). Bitwise-identical objective; the hot->cold early-reject barrier is unchanged.
- `LammpsRunner::run_script` takes the potential Context by const reference (was by value — one deep copy per sim per evaluation).
- Startup journal now logs the OpenMP pool width (`omp_get_max_threads` and `OMP_NUM_THREADS`) — the PC_LAMMPS script fan-out is capped by it.

### Fixed
- A throwing candidate-potential construction now marks the sim failed before any LAMMPS command executes (previously the EXTERN line could proceed with a null potential).

## [1.3.0-beta.1] — 2026-05-20

HPO underwent the largest restructure of any module in this release: new init strategies, resume/restart, varloss, dlib-BFGS local optimiser, the `TADAH:ANNEAL` driver family (classic + Corana adaptive variant), the `CERES` gradient-based optimiser family, and a regression-tested example suite.

### Added
- **Init strategies** — multiple ways to seed the HPO sweep (`CONFIG`, `RANDOM`, `LHS`, `SOBOL`, `WARM`); fully documented in the rewritten `hpo.rst`.
- **Resume / restart** — checkpointed long runs can be resumed from the most recent journal entry; backed by the new CORE checkpoint + signal-handler infrastructure.
- **Variance-of-loss (`varloss`) acquisition** — `--varloss` / `--outvar` flags select an alternative scoring function over a user-provided set of LAMMPS `equal`-style script variables; HPO now validates these variables exist before launching workers.
- Standalone **dlib BFGS local optimiser** — added alongside the existing nlopt path.
- `HPOLog` run journal — structured per-evaluation log written incrementally.
- Per-dataset validation metrics and stats output files.
- Per-thread `Trainer` / `TrainerHost` cache — when structural parameters do not change between evaluations, the cached object is reused via `Trainer::reinit()` instead of being reconstructed (large speed-up for sweeps that vary only weights or scalar regression parameters).
- **Reference example suite** under `HPO/examples/` with `run_reference_suite.sh` driver and per-example fingerprint files (`reference_fingerprint.json`) for regression testing.
- `TADAH_ENABLE_ASAN` CMake option.
- **`LIB TADAH ALGO ANNEAL` — classic Kirkpatrick/Metropolis Simulated Annealing driver** (refs: Kirkpatrick 1983; Metropolis 1953). Geometric cooling, fixed-shape Gaussian step in transformed-parameter space, Metropolis acceptance, auto-T0 calibration from a small uniform-bounds random walk (overridable via `PARAM T_INIT`). Tunable knobs: `T_MIN`, `RT`, `L`, `STEP_FRAC`, `T0_PROBES`, `T0_PACCEPT`. Honours `MAXEVAL`/`MAXTIME`/`STOPVAL`. Dispatched from `run_inner()` alongside `TADAH:RANDOM` / `TADAH:GRID`; reflects out-of-bound proposal components back into the box (high-dim robustness fix).
- **`ALGO ANNEAL` Corana adaptive variant** — opt-in via `PARAM CORANA 1` (refs: Corana, Marchesi, Martini, Ridella, *ACM Trans. Math. Soft.* 13:262, 1987; Brommer, Univ. Stuttgart MSc, 2003). Per-dim step vector `V[i]` adapts every `NS`-step cycle from the per-dim accept ratio (grows when rate > 0.6, shrinks when < 0.4); cools after every `NT` step-adjust cycles. Replaces classic's whole-vector Gaussian + fixed σ with one-dim-at-a-time uniform perturbation + adaptive σ — fixes the cold-T freeze that fixed-σ runs hit on continuous multimodal problems. Tunable knobs: `NS` (default 5), `NT` (default 2), `C` (default 2.0). Per-rung journal line shows `V=[V_min, V_max]`; banner shows `ANNEAL[CORANA]` vs `ANNEAL[CLASSIC]`.
- **`PARAM V_FLOOR_FRAC`** (default `1e-3`) — explicit lower clamp on `V[i]` as a fraction of bound width. Guards Corana against `V[i]` runaway collapse on `FAILSCORE`-cliff landscapes where every uphill ΔL ~ FAILSCORE rejects for any T, driving accept rate to 0.
- **`PARAM RESET_TO_BEST 1`** — step 7 of the original Corana algorithm (also used by Brommer): snap the chain back to the best-so-far point at the end of every cooling step. Gives Corana basin memory; addresses the high-T wander failure mode.
- `ANNEAL` journal trace — `hpo_run.log` records a banner echoing the resolved knobs, an extended T0 calibration line, per-cooling-rung summary lines, and an explicit `ANNEAL stopped: <reason>` end line. Lets users diagnose mistuned `T_INIT`/`RT`/`STEP_FRAC` from the journal alone.
- **`LIB CERES` family** — `LBFGS` (limited-memory BFGS, Wolfe line search), `WOLFE` (full BFGS, Wolfe line search), `NLCG` (nonlinear conjugate gradient), `STEEPEST_DESCENT` (Armijo line search). All four use Ceres' `GradientProblemSolver`; gradient via `DynamicNumericDiffCostFunction` (central differences; step from `PARAM fd_step`). The Ceres NLLS family is deferred at dispatch with a tailored error.
- **`OptimizerCaps` registry** — single source of truth for `(LIB, ALGO)` capabilities (`is_global` / `is_population` / `is_gradient_based` / `accepts_inner` / `accepts_multi_seed` + ftol routing discriminant). Adding new optimisers is now two changes (run-function + caps entry).
- **`PC_LAMMPS --hotvar <name> <min> <max> [<initial>]`** — declares a `PC_LAMMPS` line as *hot*: a two-phase evaluator. Hot scripts run alone in **phase A** of each iteration (in parallel with other hot scripts), expose a value via `variable <name> equal …`, and have it validated against `[min, max]`. Validated values are cached per `(script, name)` and propagated as `${<name>}` strings to every cold (no-`--hotvar`) `PC_LAMMPS` script in **phase B**. Multiple `--hotvar` flags per line allowed; phase A is parallel so no cross-references. Out-of-range hot values fail-score the iteration and skip phase B.
- **`PC_<METRIC> --skip-above <cap>` / `--skip-rel <ratio>`** — per-metric bad-pot pre-filter on `PC_EMAE`, `PC_ERMSE`, `PC_ErRMSE`, `PC_ERSQ`, `PC_FRMSE`, `PC_SRMSE`. Triggers fire *before* the LAMMPS phase, fail-scoring the iter when the metric exceeds the cap or `metric > ratio × running_best` for the same metric.
- **Pre-flight audit hook + per-iter health monitor** — wires the MLIP bound-validation pipeline into the HPO surface. Driven by blueprint keys `AUDIT`, `AUDIT_SAMPLE`, `HEALTH_LOG` (in CORE).
- **`EFILTER` / `FFILTER` forwarded from `--validation`** — the validation-side LOAD-TRANSFORMS path now respects the same energy/force filtering as training. Symmetric LOAD-TRANSFORMS log; mean-share breakdown.

### Changed

## [1.2.0] and earlier (condensed)

The `v1.0.0` → `v1.1.1` releases were the "internal playground" era. HPO began life as a small NLOpt wrapper; releases in this period focused on build-system iteration so that HPO could co-build with LAMMPS (CMake + traditional make), `FAIL_SCORE` defaulting, the move to `PC_<type>` performance counters, and a sequence of small fixes. No published changelog covers this era; treat anything before `1.3.0-beta.1` as undocumented in the modern sense.
